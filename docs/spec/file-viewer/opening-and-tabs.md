# 開き方とタブ

Files ツリーでファイルを押したときに、どのタブにどう開くか。[File viewer 仕様](index.md)の一部。

## ツリーで押したら viewer のタブに開く

`file-tree` でファイルを押すと、Files パネルの中ではなく、メイン領域の viewer のタブ（`file-viewer` の mod だけが入ったタブ）に開く。フォルダを押したときの展開・折りたたみは同梱 Files と同じ。

- 成功条件: ツリーでファイルを押すと viewer のタブが前面に出て、そのファイルが表示される。Files パネルには表示されない。
- 反例: 押したファイルが Files パネルの中に表示され、ツリーが隠れる（同梱 Files の動き）。
- 確かめ方: 実機で押し、`herdr-app ls` でタブが増えたことと、`herdr-app shot` で表示を見る。

## プレビュータブ

ツリーでシングルクリックしたファイル（と、Markdown 内のリンク・画像から開いたファイル）は、その space の[プレビュータブ](../../../CONTEXT.md#プレビュータブ)に開く。プレビュータブは space ごとに 1 つ。プレビュータブがすでにあれば、新しいタブを作らずにその中身を押したファイルに入れ替える。

次のどれかでプレビュータブは[固定タブ](../../../CONTEXT.md#固定タブ)になり、以後は入れ替わらない。

- ツリーでファイルをダブルクリックする。ダブルクリックしたファイルは、プレビュータブがあればその中身を入れ替えてそのタブを固定し、無ければ固定タブとして開く
- viewer の「固定」ボタンを押す
- そのタブで編集する

- 成功条件: ツリーで a.js → b.js とシングルクリックすると、タブは 1 つのまま中身が b.js になる。a.js をダブルクリックしてから b.js をシングルクリックすると、a.js の固定タブと b.js のプレビュータブの 2 つになる。プレビュータブに a.js が出ているときに c.js をダブルクリックすると、タブは 1 つのまま c.js の固定タブになる。
- 反例: シングルクリックのたびにタブが増える。編集した後のタブが、別のファイルを押したときに入れ替わって編集が消える。
- 確かめ方: 実機で上の操作をし、`herdr-app ls` のタブ数とタブ名を見る。

## 同じファイルは既存のタブに切り替える

押したファイルのタブ（プレビュー・固定のどちらでも）が今の space にすでにあれば、新しく開かずにそのタブに切り替える。シングルクリックで固定タブに切り替えたとき、そのタブはプレビューに戻らない。ダブルクリックで切り替えた先がプレビュータブなら、そのタブを固定する。既存タブは今の space の中でだけ探す。別の space に同じファイルのタブがあっても移動しない。

- 成功条件: 固定タブで開いている a.js を再び押すと、そのタブが前面に出て、タブ数は変わらない。
- 反例: 同じファイルのタブが同じ space に 2 つできる。押したら別の space に切り替わる。
- 確かめ方: 実機で操作し、`herdr-app ls` を見る。

## タブ名

タブ名はファイル名。同じ space に同じファイル名のタブが複数あるときだけ、親フォルダ名を添える（例: `main.js · files`）。プレビュータブは先頭に `◇ `、未保存の編集があるタブは末尾に ` ●` を付ける。

- 成功条件: プレビュータブで開いた `main.js` のタブ名は `◇ main.js`。固定して編集すると `main.js ●`。別フォルダの `main.js` も開くと、両方に親フォルダ名が付く。
- 反例: タブ名がパス全体になる。未保存なのに印が付かない。
- 確かめ方: タブ名を決める処理を単体テストで確かめる（ファイルの一覧と状態を入力し、タブ名を出力として比べる）。実機では `herdr-app ls` で見る。

## タブの位置

新しく開くタブは、今のタブのすぐ右に置く。

- 成功条件: 3 つあるタブの 1 番目を見ている状態で新しいファイルを開くと、新しいタブは 2 番目になる。
- 反例: 新しいタブが常に末尾に付く。
- 確かめ方: 実機で開き、`herdr-app ls` の並びを見る。

## 再起動後の復元

アプリを再起動すると、viewer のタブは同じファイルをディスクから読み直して開く。プレビュー / 固定の状態と、表示の切り替え（Markdown の整形 / ソース、SVG と .mmd の画像・図 / ソース）も保つ。ファイルが無くなっていたら[ファイルが消えたら](editing.md#ファイルが消えたら)と同じ扱いにする。未保存だった編集は[下書き](editing.md#下書き)から復元を聞く。

- 成功条件: プレビュータブと、ソース表示に切り替えた固定タブがある状態で再起動すると、同じ 2 つのタブが同じ状態で戻る。
- 反例: 再起動後、プレビュータブが固定タブになっている。ソース表示が整形表示に戻っている。
- 確かめ方: 実機で再起動し、`herdr-app ls` と `herdr-app shot` で見る。

## viewer のタブを見ている間のツリー

viewer のタブを見ている間、Files ツリーは直前に表示していたフォルダと展開状態を保つ。ターミナルのペインにフォーカスが戻れば、またそのペインのフォルダに追従する。

- 成功条件: ターミナルで `docs/` にいてツリーから `guides/a.md` を押すと、viewer のタブに移った後もツリーは `docs/` を表示したままで、`guides/` も展開されたまま。続けて別のファイルを押せる。
- 反例: viewer のタブに移った瞬間、ツリーが space のフォルダに切り替わる（同梱 Files の動き）。
- 確かめ方: 実機で操作し、`herdr-app shot` で見る。

## 見送った案

- 押すたびに新しいタブ（プレビュー方式なし） — 眺めて回るとタブが増え続ける
- タブ名をリポジトリからの相対パスにする — タブが長くなる
- 新しいタブを末尾に置く — タブが多いと遠くに開く
- viewer のタブにいる間、ツリーを space のフォルダに切り替える（同梱 Files の動き） — 開くたびに表示元が変わり、続けて開きにくい
- どの space でも既存タブへ移動する — 押すと別の space に飛ぶ
- プレビュータブを全体で 1 つにする — space を切り替えるとプレビューが消える
- 再起動後は状態を既定に戻す — プレビュータブが固定タブとして残る
