# Mermaid 図

Markdown 内の Mermaid と Mermaid 単体のファイルを、図として描く。[File viewer 仕様](index.md)の一部。

## 描く図

Markdown の整形表示で、` ```mermaid ` のコードブロックを図として描く。描く種類は flowchart（`graph` / `flowchart`）と `sequenceDiagram`。図はブロックのあった位置に、本文の幅に収まるよう縮めて置く。

描く書き方の範囲:

| 種類 | 範囲に含む | 範囲外 |
|---|---|---|
| flowchart | 向き（TD / TB / BT / LR / RL）、主なノードの形（四角・角丸・円・ひし形・平行四辺形など）、矢印の種類（`-->` / `---` / `-.->` / `==>`）とラベル、`subgraph`、`style` / `classDef` / `class` の色 | `click`（リンク）、アイコン、markdown 文字列のノード |
| sequenceDiagram | `participant` / `actor`（`as` の別名も）、矢印（`->>` / `-->>` / `->` / `-->` / `-x` / `--x`）とメッセージ、`Note`（`left of` / `right of` / `over`）、`alt` / `else` / `opt` / `loop`、`activate` / `deactivate`（`+` / `-` 記法も） | `autonumber`、`rect` の背景色、`par` / `critical` / `break`、`box` |

- 成功条件: `flowchart LR; A-->B; B-->C` のブロックが、A→B→C の 3 つの箱と矢印で描かれる。`sequenceDiagram` のブロックが、参加者の列とメッセージの矢印で描かれる。
- 反例: コードブロックのまま表示される。図が本文の幅からはみ出す。
- 確かめ方: 文法の解析と配置の処理は単体テストで確かめる（Mermaid の文を入力し、ノード・辺・参加者・メッセージの並びを出力として比べる）。見た目は実機で `herdr-app shot` で見る。

## 描けない図

flowchart / sequenceDiagram 以外の種類、または文法の誤りで描けないときは、コードブロックのまま表示し、その上に「この図は表示できない」と理由を添える。理由は次の 3 つのどれか。行番号は Markdown ファイル全体での行番号（.mmd ではそのファイルの行番号）で、ソース表示の行番号と一致する。

- 未対応の種類（`classDiagram` など、種類名を出す）
- 未対応の書き方（[範囲外](#描く図)の書き方。例: 「未対応の書き方: click（43 行目）」）
- 文法エラー（例: 「43 行目の文法エラー」）

- 成功条件: `classDiagram` のブロックは、コードのまま表示され、上に「未対応の種類: classDiagram」が出る。README の 41 行目から始まるブロックの中で、ブロック内 3 行目（ファイルの 43 行目）に誤りのある flowchart は、「43 行目の文法エラー」が出る。
- 反例: 何も表示されない。理由なしにコードのまま表示される。
- 確かめ方: 理由を作る処理を単体テストで確かめる。実機で `herdr-app shot` で見る。

## 拡大表示

図を押すと、タブの上に重ねる窓（overlay）を開き、[image viewer](viewers.md#image-viewer) と同じ操作（ズーム・ドラッグ・等倍 / 収まる大きさ）で拡大して見られる。タブは増えない。Esc か閉じるボタンで閉じる。

- 成功条件: 本文の幅で縮んで読みにくい図を押すと、拡大表示が開き、ctrl+ホイールで拡大できる。
- 反例: 図を押しても何も起きない。
- 確かめ方: 実機で操作し、`herdr-app shot` で見る。

## 色

図の線・文字・枠は herdr のテーマ色に従う。flowchart の `style` / `classDef` / `class` の色指定（塗り・線・文字の色）は反映する。

- 成功条件: ライトとダークのテーマを切り替えると、図の色もそれに合わせて変わる。
- 反例: ダークテーマで黒い線が背景に溶ける。
- 確かめ方: 実機でテーマを切り替え、`herdr-app shot` で見る。

## Mermaid 単体ファイル

`.mmd` / `.mermaid` のファイルは図として表示し、ボタンでソース表示（code viewer）に切り替えられる。編集はソース表示で行う。描けない場合は[描けない図](#描けない図)と同じ扱い。

- 成功条件: `flow.mmd` を開くと図が表示され、ソース表示に切り替えて編集できる。
- 反例: `.mmd` が code viewer でしか開けない。
- 確かめ方: 実機で開き、`herdr-app shot` で見る。

## 同梱してよいライブラリ

図の配置などに外部の JS ライブラリを使う場合は、許容的なライセンス（MIT など）の純 JS ライブラリに限る。mod の実行環境で動くことを試験で確かめてから採用し、ライセンス表記も同梱する。

- 成功条件: 同梱したライブラリごとに、ライセンス表記のファイルがリポジトリにある。
- 反例: GPL のライブラリ、DOM や Node の機能を前提にするライブラリを同梱する。
- 確かめ方: 人がライセンス表記と同梱ファイルを確認する。

## 見送った案

- Mermaid をコードブロックのまま表示する — 図として見たい（Orca 相当）
- flowchart だけ / 主要 5 種をまとめて — シーケンス図が描けないか、作業量が大きく増える
- ox-content や mermaid.js をそのまま使う — Node ネイティブ拡張・DOM 前提で、mod の実行環境（QuickJS、WebAssembly 無し）では動かない
- machine 側の Mermaid CLI（mmdr など）に描かせる — 使う machine ごとに CLI のインストールが要る。mod 内で描けばどの machine でも追加のインストールなしで図が出る
- 描けない図を黙ってコードのまま表示する — 未対応か書き間違いか区別できない
- 等倍で描き、はみ出す分は横スクロール — 大きな図を見渡しにくい
- Mermaid の既定配色に寄せる — テーマによっては浮く
- flowchart は四角・ひし形・矢印だけ / sequenceDiagram は participant と矢印だけ — subgraph や条件分岐・注記のある図が描けない
- 行番号をコードブロックの中で数える — ソース表示で行を探すのに足し算が要る
- 拡大表示を新しい viewer のタブで開く — タブが増える
- ライブラリを一切使わず全部自作する — 自動配置の作業がかなり重い
