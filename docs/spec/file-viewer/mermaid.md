# Mermaid 図

Markdown 内の Mermaid と Mermaid 単体のファイルを、図として描く。[File viewer 仕様](index.md)の一部。

## 描く図

Markdown の整形表示で、` ```mermaid ` のコードブロックを図として描く。描く種類は flowchart（`graph` / `flowchart`）と `sequenceDiagram`。図はブロックのあった位置に、本文の幅に収まるよう縮めて置く。

描く書き方の範囲:

| 種類 | 範囲に含む | 範囲外 |
|---|---|---|
| flowchart | 向き（TD / TB / BT / LR / RL）、主なノードの形（四角・角丸・円・ひし形・平行四辺形など）、矢印の種類（`-->` / `---` / `-.->` / `==>`）とラベル、`subgraph`、`style` / `classDef` / `class` の色 | `click`（リンク）、アイコン、markdown 文字列のノード |
| sequenceDiagram | `participant` / `actor`（`as` の別名も）、矢印（`->>` / `-->>` / `->` / `-->` / `-x` / `--x`）とメッセージ、`Note`（`left of` / `right of` / `over`）、`alt` / `else` / `opt` / `loop`、`activate` / `deactivate`（`+` / `-` 記法も） | `autonumber`、`rect` の背景色、`par` / `critical` / `break`、`box` |

- 成功条件: `flowchart LR; A-->B; B-->C` のブロックが、A→B→C の 3 つの箱と矢印で描かれる。`sequenceDiagram` のブロックが、参加者の列とメッセージの矢印で描かれる。
- 反例: コードブロックのまま表示される。図が本文の幅からはみ出す。
- 確かめ方: 文法の解析と配置の処理は単体テストで確かめる（Mermaid の文を入力し、ノード・辺・参加者・メッセージの並びを出力として比べる）。見た目は実機で `herdr-app shot` で見る。

## 描き方

図は、配置した図を SVG 画像に書き出し、その画像 1 つとして描く（整形表示の図、[拡大表示](#拡大表示)、[Mermaid 単体ファイル](#mermaid-単体ファイル)のすべて）。箱・線・文字を一つずつの部品として組み立てて描くことはしない（図が多いと描き直しのたびに重くなり、描画が打ち切られるため）。

- Markdown の図の書き出しは[整形の準備](viewers.md#整形の準備)に含める。[拡大表示](#拡大表示)と[Mermaid 単体ファイル](#mermaid-単体ファイル)の書き出しも、整形の準備と同じく描画の外で行う。書き出していない図を空きのまま見せることはしない（待つ間の見え方は整形の準備と、それぞれの節の決まりに従う）。
- 書き出した SVG は、[image viewer](viewers.md#image-viewer) の画像のコピーと同じ `file-viewer-cache/` に、タブ・図の中身・色・書き出しの大きさから決まる名前で置く（同じ名前のファイルを上書きしない）。古い SVG は、それを出している表示（前の整形表示、前の色の絵、前の倍率の絵、それを開いている拡大の窓）が替わるか閉じてから消し、タブを閉じたら消す。起動後の掃除では、どのタブも表示していない SVG は消してよく、そのタブを表示したときに書き直す。書き出し済みのはずのファイルが無くなっていたら書き直す。
- 図の中身と色と書き出しの大きさが変わらない限り、SVG を書き直さない。
- 図の中の文字（ノードの名前、矢印のラベル、`subgraph` の題名、参加者・メッセージ・注記）は、今までの図と同じ字体・太さで描く。同じ字体を SVG で指定できるかは実装の最初に確かめてガイドに書き、できなければ、いちばん近い字体にして、部品で描いた図と並べた画像を作業者に見せ、受け入れるかを作業者が決める。文字の幅は、SVG で描く字体で測って箱の大きさを決め、文字を箱からはみ出させない。どのノードの名前も欠けずに出る。
- 表示上の違和感が無いこと: 部品で描いていたときの図と並べて、大きさ・色・線・文字の位置と字体が見比べて違和感の無いものにする（違和感が無いかは作業者が見て決める）。画像を引き伸ばした・縮めた絵は、一瞬も見せない。

- 成功条件: 図の数が[整形表示の上限](viewers.md#整形表示の上限)ちょうどの Markdown を開いても描き直しやスクロールで止まらず、どの図もノードの名前が全部出る。ひし形のノードや丸いノードの名前も、倍率を変えたあとやスクロールのあとに消えない。部品で描いていたときの図と並べた画像で、字体や線の太さに違和感が無い。
- 反例: 図の多い Markdown で「This view could not be re-rendered」と「interrupted」が出る。ノードの名前の一部が出ない。図が一瞬空いてから出る。拡大したときにぼやけた絵が見える。`file-viewer-cache/` に SVG が溜まり続ける。
- 確かめ方: 配置から SVG の文字列を作る処理は単体テストで確かめる（ノード・辺・文字・色が SVG の要素として出ること）。見た目は[確かめ専用の窓](index.md#実機の確かめ)で `herdr-app shot` で撮り、部品で描く作りのコミットで同じ図を先に撮っておいた画像と並べて、作業者が見る。

## 描けない図

flowchart / sequenceDiagram 以外の種類、文法の誤り、または（[Mermaid 単体ファイル](#mermaid-単体ファイル)で）図の準備の時間切れや書き出しの失敗で描けないときは、コードブロックのまま表示し、その上に「この図は表示できない」と理由を添える。理由は次の 5 つのどれか。行番号は Markdown ファイル全体での行番号（.mmd ではそのファイルの行番号）で、ソース表示の行番号と一致する。

- 未対応の種類（`classDiagram` など、種類名を出す）
- 未対応の書き方（[範囲外](#描く図)の書き方。例: 「未対応の書き方: click（43 行目）」）
- 文法エラー（例: 「43 行目の文法エラー」）
- 図の準備が終わらなかった（[Mermaid 単体ファイル](#mermaid-単体ファイル)だけ。図の準備が 10 秒たっても終わらなかったとき）
- 図を書き出せなかった（[Mermaid 単体ファイル](#mermaid-単体ファイル)だけ。最初の SVG の書き出しが失敗したとき。理由を添える）

- 成功条件: `classDiagram` のブロックは、コードのまま表示され、上に「未対応の種類: classDiagram」が出る。README の 41 行目から始まるブロックの中で、ブロック内 3 行目（ファイルの 43 行目）に誤りのある flowchart は、「43 行目の文法エラー」が出る。
- 反例: 何も表示されない。理由なしにコードのまま表示される。
- 確かめ方: 理由を作る処理を単体テストで確かめる。実機で `herdr-app shot` で見る。

## 拡大表示

図を押すと、タブの上に重ねる窓（overlay）を開き、[image viewer](viewers.md#image-viewer) と同じ操作（ズーム・ドラッグ・等倍 / 収まる大きさ）で拡大して見られる。タブは増えない。Esc か閉じるボタンで閉じる。

拡大の窓と `.mmd` の表示では、倍率（窓の大きさに収める倍率を含む）が変わったら、その表示の大きさで SVG を書き出し直して出し、どの倍率でもくっきり描く。書き終わるまでは、前の倍率の絵をその大きさのまま出す（拡大でも縮小でも、引き伸ばしも縮めもしない。その間、倍率の操作は絵に表れない）。続けて倍率を変えたときは、最後の倍率の分だけ書き出す。

- 拡大の窓は、開いたときの図の SVG を閉じるまで持ち、倍率の書き出し直しはそこから行う（窓を開いたあと本文が差し替わっても、窓の中は古い図のまま書き直せる）。
- 図を押したら、窓に収まる大きさの SVG を書き終えてから窓を開く。1 秒たっても書けなければ、本文の SVG を引き伸ばさずに本来の大きさで出して窓を開き、書けたら収まる大きさに替える。
- 倍率を変えたときの書き出し直しが失敗したら、または 10 秒たっても終わらなかったら、前の倍率の絵のまま出し続け、窓の中に「図を書き出せなかった（理由）」と知らせる（知らせるだけのもので、次に書き出せたら消える）。

- 成功条件: 本文の幅で縮んで読みにくい図を押すと、拡大表示が開き、ctrl+ホイールで拡大できる。開いた時点で、窓に収まる大きさのくっきりした絵が出る。3 倍以上に拡大しても線と文字がくっきりしている。重い図を押しても拡大表示が止まらない。
- 反例: 図を押しても何も起きない。拡大するとぼやける。拡大した直後に、引き伸ばしたぼやけた絵が見える。窓を開いた直後に、小さい絵や空きが見える。
- 確かめ方: 書き出しの大きさと、待つ間に出す絵を決める処理は単体テストで確かめる。[確かめ専用の窓](index.md#実機の確かめ)で操作し、`herdr-app shot` で見る。

## 色

図の線・文字・枠は herdr のテーマ色に従う。flowchart の `style` / `classDef` / `class` の色指定（塗り・線・文字の色）は反映する。

色は SVG に書き込むので、テーマを変えたら新しい色で書き出し直す。書き終わるまでは前の色の絵を出し、文書の図が全部そろったらまとめて替える（整形表示を「整形中…」に戻さない。新旧の色の図を混ぜて見せない）。拡大の窓と `.mmd` の図も同じく替える。

- テーマの書き出し直しは[整形の準備](viewers.md#整形の準備)の 1 つとして扱う。表示しているときだけ動かし、10 秒の決まりに従い、途中で中身が変わったら新しい中身と新しい色でやり直す。タブを表示していない間にテーマが変わったら、表示に戻ったときに書き出し直す（書き終わるまでは前の色の絵）。
- 書き出し直しが失敗したら、前の色の絵のまま出し続け、「図を書き出せなかった（理由）」と知らせる（知らせるだけのもので、次に書き出せたら消える）。10 秒たっても終わらなかったときも同じく、前の色の絵のまま「整形の準備が終わらなかった」と知らせる。どちらも整形表示を代わりの整形表示にはしない。

- 成功条件: ライトとダークのテーマを切り替えると、図の色もそれに合わせて変わる。
- 反例: ダークテーマで黒い線が背景に溶ける。テーマを変えると整形表示が消えて「整形中…」になる。古い色と新しい色の図が混ざって見える。
- 確かめ方: テーマが変わったときにまとめて替える順は単体テストで確かめる。[確かめ専用の窓](index.md#実機の確かめ)でテーマを切り替え、`herdr-app shot` で見る。

## Mermaid 単体ファイル

`.mmd` / `.mermaid` のファイルは図として表示し、ボタンでソース表示（code viewer）に切り替えられる。編集はソース表示で行う。描けない場合は[描けない図](#描けない図)と同じ扱い。

図の解析・配置と SVG の書き出しは、Markdown の[整形の準備](viewers.md#整形の準備)と同じく描画の外で行う（大きさで描画の中と外を分けない。図 1 つが区切りの単位になる）。

- 図に入るとき（開く、ソース表示から戻る、[プレビュータブ](opening-and-tabs.md#プレビュータブ)の中身が入れ替わる）は、済むまで図の場所に「整形中…」を出す。図を出したまま中身やテーマが変わったときは、前の図を出し続け、済んだら差し替える。
- 準備は表示しているときだけ動かす。10 秒（表示している間だけ数える）たっても終わらなければ、[描けない図](#描けない図)の「図の準備が終わらなかった」として出す。最初の書き出しが失敗したら「図を書き出せなかった」として出す。どちらも、中身が変わったら準備をやり直す。

- 成功条件: `flow.mmd` を開くと図が表示され、ソース表示に切り替えて編集できる。ノードが数百ある大きな `.mmd` を開いても、「This view could not be re-rendered」と「interrupted」が出ない。
- 反例: `.mmd` が code viewer でしか開けない。大きな `.mmd` を開くと描画が打ち切られる。「整形中…」のまま進まない。外から書き換えるたびに「整形中…」がちらつく。
- 確かめ方: 図に入るときと中身が変わったときの見え方を決める処理は単体テストで確かめる。[確かめ専用の窓](index.md#実機の確かめ)で開き、`herdr-app shot` で見る。

## 同梱してよいライブラリ

図の配置などに外部の JS ライブラリを使う場合は、許容的なライセンス（MIT など）の純 JS ライブラリに限る。mod の実行環境で動くことを試験で確かめてから採用し、ライセンス表記も同梱する。

- 成功条件: 同梱したライブラリごとに、ライセンス表記のファイルがリポジトリにある。
- 反例: GPL のライブラリ、DOM や Node の機能を前提にするライブラリを同梱する。
- 確かめ方: 人がライセンス表記と同梱ファイルを確認する。

## 見送った案

- Mermaid をコードブロックのまま表示する — 図として見たい（Orca 相当）
- flowchart だけ / 主要 5 種をまとめて — シーケンス図が描けないか、作業量が大きく増える
- ox-content や mermaid.js をそのまま使う — Node ネイティブ拡張・DOM 前提で、mod の実行環境（QuickJS、WebAssembly 無し）では動かない
- machine 側の Mermaid CLI（mmdr など）に描かせる — 使う machine ごとに CLI のインストールが要る。mod 内で描けばどの machine でも追加のインストールなしで図が出る
- 描けない図を黙ってコードのまま表示する — 未対応か書き間違いか区別できない
- 等倍で描き、はみ出す分は横スクロール — 大きな図を見渡しにくい
- Mermaid の既定配色に寄せる — テーマによっては浮く
- flowchart は四角・ひし形・矢印だけ / sequenceDiagram は participant と矢印だけ — subgraph や条件分岐・注記のある図が描けない
- 行番号をコードブロックの中で数える — ソース表示で行を探すのに足し算が要る
- 拡大表示を新しい viewer のタブで開く — タブが増える
- ライブラリを一切使わず全部自作する — 自動配置の作業がかなり重い
- 図を箱・線・文字の部品で組み立てて描き、図の数の上限を 50 個ほどに下げる — 図の多い文書が整形表示できず、ノードの名前が欠ける不具合も残る
- 等倍の図は SVG 画像、拡大したときは部品で描く — 拡大の窓で名前が欠ける不具合が残り、拡大の前後で見た目が変わる
- 見えている所だけを描く遅延リストで整形表示を描く — 文章の中のリンクが押せず、差し替えでスクロールの位置が先頭に戻る（試験で確認）
- 拡大したら書き直すまで引き伸ばした絵を出す — ぼやけた絵が見える
- テーマを変えたら「整形中…」に戻す / 書き終わった図から順に替える — 整形表示が消える / 新旧の色の図が混ざって見える
- `.mmd` も小さい図は描画の中で準備する — 分け方の値をもう 1 組測って持つことになる
- SVG 専用のキャッシュを別に持つ — 消す仕組みをもう 1 つ持つことになる
- SVG の書き出しの失敗を、場面によらず全部失敗の道（代わりの整形表示）に入れる — テーマを変えただけで整形表示が崩れる
- 拡大の窓をすぐ開き、本文の SVG を本来の大きさで出してから替える / 書けるまで「整形中…」を出す — 開いた直後に絵の大きさが変わる / 押すたびに一瞬「整形中…」が出る
- 同じ字体にできなければ SVG の作りをやめる — 字体が合わないと、図の重さの問題が解けないまま止まる
