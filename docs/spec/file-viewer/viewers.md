# viewer

開いたファイルを、内容に合った viewer で表示する。[File viewer 仕様](index.md)の一部。編集と保存は[編集・保存と外部変更](editing.md)にある。

## 種類の判定

次の順で振り分ける。拡張子は大文字小文字を区別しない。

1. 拡張子で画像・Markdown・Mermaid を決める（下の表）。
2. 大きさが[上限](#上限)を超えていれば、開けないファイルの案内にする。上限は、画像（SVG を含む）が画像の上限、それ以外（Markdown・Mermaid を含む）がテキストの上限。
3. 画像以外はテキストとして読み、NUL を含めば[開けないファイル](#開けないファイル)にする。含まなければ、1 で決めた viewer（決まっていなければ code）で開く。

| 拡張子 | viewer |
|---|---|
| png / jpg / jpeg / gif / webp / bmp / ico | image |
| svg | image（ソース表示に切り替えられる） |
| md / markdown | markdown |
| mmd / mermaid | Mermaid 図（[Mermaid 単体ファイル](mermaid.md#mermaid-単体ファイル)） |
| それ以外（拡張子が無いものを含む） | テキストとして読み、NUL を含めば[開けないファイル](#開けないファイル)、含まなければ code |

- 成功条件: `Makefile` は code、`logo.SVG` は image、`a.bin`（NUL を含む）は開けないファイルの案内になる。
- 反例: 拡張子の無いテキストがバイナリ扱いになる。
- 確かめ方: 判定処理を単体テストで確かめる（パスと内容を入力し、viewer の種類を出力として比べる）。

## 上限

テキストは 1 MiB（1,048,576 バイト）、画像は 6,000,000 バイトまで開く（画像は base64 にして運ぶので、コマンド出力の上限 8 MiB に収まる大きさ）。超えたら開けないファイルの案内に、上限を超えていることとファイルの大きさを出す。

- 成功条件: 2 MiB のログを開くと「大きすぎる（上限 1 MiB、このファイル 2.0 MiB）」のような案内が出る。
- 反例: 黙って空や途中までの内容が表示される。
- 確かめ方: 実機で上限を超えるファイルを開き、`herdr-app shot` で見る。上限の判定と文言を作る処理は単体テストで確かめる。

### 整形表示の上限

テキストの上限より小さくても、整形表示の部品や図を描くのに時間がかかりすぎる Markdown は、整形表示をせずソース表示で開く。整形表示の上限は 2 つの値で、今の内容（保存前の編集を含む）を UTF-8 にしたバイト数と、` ```mermaid ` の図の数。どちらかが上限を超えたら（ちょうどは含まない）整形表示をしない。時間がかかりすぎるとは、整形表示を開いたときやスクロールしたときに、app が操作を受け付けない時間が 1 秒以上になること。

- ソース表示で開いたときは、整形表示をしない理由として、整形表示の上限の値と今の大きさ（バイト数か図の数のうち超えたほう）を出す。この知らせは知らせるだけのもので（並べ方は[ほかの知らせが出ているとき](editing.md#ほかの知らせが出ているとき)）、閉じられず、上限を下回ったら消える。
- 上限を超えている間は、整形表示に切り替えるボタンを出さない（[SVG](#svg) の、1 MiB を超えるとソース表示のボタンを出さないのと同じ形）。
- 上限を比べるのは、整形表示に入るとき（[整形の準備](#整形の準備)の「整形表示に入るとき」）と、中身が変わるたび（整形表示でもソース表示でも）。整形表示のまま上限を超えたら、ソース表示に移して理由を出す。上限を超えたことでソース表示にしたタブは、上限を下回っても自動では整形表示に戻さない（編集の途中で画面が切り替わらないように）。知らせを消し、整形表示に切り替えるボタンを出す。整形表示に戻るのは、利用者がボタンを押したときと、タブを開き直したとき・再起動したとき（覚えた表示に従う）。タブごとに覚える表示（[再起動後の復元](opening-and-tabs.md#再起動後の復元)を含む）は利用者が選んだものだけで、上限で移したソース表示は覚えない。再起動後は、覚えた表示を上限で比べ直す。
- 値は実機で測る。バイト数は、見出し・表・コードブロック・リンクを含み図の無い Markdown を、図の数は見出し・段落・図の組を並べた Markdown を、大きさを変えて開いて測る（図の数は、開いた直後と、重い文書（上限の近くの、画像や図の多い文書）を開いて閉じたあとの両方で、描き直しやスクロールでも止まらない数にする）。測るのは[確かめ専用の窓](index.md#実機の確かめ)で、止まった時間は、スクロールなどの操作を送ってから `herdr-app shot` の画面が変わるまでを、続けて撮って測る。撮る間隔は 200 ms 以下を目安にし（できなければそのことをガイドに書く）、上限の近く（±10%）は 3 回測って、どれも 1 秒未満なら止まらないとする。図の数の値は、図を [SVG 画像で描く](mermaid.md#描き方)作りで測る。バイト数の値は図の描き方に関係しないので、部品で描く作りのときに測った値をそのまま使う。測った図の数の上限が 64 以下なら、下の成功条件を満たせないので、この仕様を見直す。測った値は [mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)の「制約」とコードの定数に書き、この仕様には書かない（値が変わってもこの仕様は直さない）。

- 成功条件: 整形表示の上限を超える Markdown を開くとソース表示で開き、上限の値と今の大きさが出て、整形表示に切り替えるボタンが無い。上限より小さい、見出し・表・コードブロックの多い Markdown と、図の数が上限ちょうどの Markdown は整形表示で開き、開いたときもスクロールしたときも app が 1 秒以上止まらない。整形表示のまま外から書き換えられて上限を超えるとソース表示に移る。そのタブをソース表示のまま編集して上限を下回ると、知らせが消えて整形表示に切り替えるボタンが出る（表示はソースのまま）。
- 反例: 整形表示を開いたとき、app 全体が 1 秒以上固まる。自分でソース表示を選んだタブが、勝手に整形表示に戻る。ソース表示で編集している途中で、整形表示に切り替わる。
- 確かめ方: 上限で表示を選ぶ処理（自分で選んだソース表示と、上限で移したソース表示の区別を含む）は単体テストで確かめる。上限の前後の大きさの Markdown を[確かめ専用の窓](index.md#実機の確かめ)で開いてスクロールし、`herdr-app shot` で見る。

## code viewer

コード表示の部品（Editor）で表示する。行番号・拡張子に応じた色分け・折りたたみを持ち、色は herdr のテーマ色に従う。折り返しの切り替えボタンを持つ。ファイル内検索は、部品の内部に検索があればそれを使い、無ければ持たない。

- 成功条件: `.js` を開くと行番号と色分けが付き、折り返しボタンで長い行が折り返される。
- 反例: 色分けがテーマと無関係な固定色になる。
- 確かめ方: 実機で開き、`herdr-app shot` で見る。

## markdown viewer

既定は整形表示。ボタンでソース表示（code viewer と同じ部品）に切り替えられ、編集はソース表示で行う。どちらの表示にしているかはタブごとに覚える。ただしプレビュータブの中身が別のファイルに入れ替わったら、既定（整形表示）に戻す（[整形表示の上限](#整形表示の上限)を超えるときはソース表示）。整形表示は、保存前の編集中の内容も含めて、そのタブの今の内容を表示する（[整形の準備](#整形の準備)の間だけの例外がある）。

- 成功条件: `README.md` を開くと見出し・表・コードブロックが整形されて表示される。ソース表示で見出しを書き換えて整形表示に戻すと、書き換えた見出しが表示される。
- 反例: 整形表示がディスク上の古い内容を表示する。タブを切り替えて戻ると表示方法が既定に戻る。
- 確かめ方: 実機で操作し、`herdr-app shot` で見る。

### リンク

整形表示のリンクを押したとき:

- 相対パスのリンク（`[設計](docs/design.md)`）は、Markdown ファイルのフォルダを基準にファイルを解決し、viewer のタブで開く。`#見出し` が付いていれば `#` 以降を除いてファイルを開く（見出しへの移動はしない。部品に見出しへ移動する機能が見当たらないため）。同じファイル内の `#見出し` だけのリンクは何もしない。開き方は[プレビュータブ](opening-and-tabs.md#プレビュータブ)と[既存タブへの切り替え](opening-and-tabs.md#同じファイルは既存のタブに切り替える)に従う。
- `http://` / `https://` のリンクはブラウザで開く。
- 解決したファイルが無ければ、そのことを知らせて何も開かない。
- 解決した先がフォルダなら、「リンク先はフォルダなので開けない」と知らせて何も開かない。無いときの知らせとは分ける。

- 成功条件: `README.md` 内の `[ガイド](docs/guide.md)` を押すと、`docs/guide.md` が viewer のタブで開く。`[docs](docs/)` を押すと、フォルダなので開けないと知らされ、タブは増えない。
- 反例: 相対リンクを押しても何も起きない、またはブラウザが開く。実在するフォルダへのリンクで「ファイルが無い」と知らされる。
- 確かめ方: パスの解決処理を単体テストで確かめる。実機で押して `herdr-app ls` を見る。

### スクロールバー

整形表示の本文の右端のスクロールバーは、app のほかの場所のスクロールバー（Files のツリーなど）と同じように見えて動く。

- つまみの長さは、本文の場所の高さと本文の高さの比で溝の長さを分けた長さにする。短くなりすぎないよう下限を持つ。つまみのドラッグと、溝を押すことで位置を動かせる。
- 色・幅・出し入れは app のスクロールバーに合わせる。スクロールしたときに出て、少したつと消える。つまみにマウスを載せている間は出たままにする。

- 成功条件: 長い文書では短い文書よりつまみが短い。ホイールでスクロールするとスクロールバーが出て、最後のスクロールから約 2 秒で消える。つまみにマウスを載せている間は、2 秒たっても出たまま。
- 反例: 文書の長さが変わってもつまみの長さが変わらない。スクロールしてもスクロールバーが出ない、または出たまま消えない。
- 確かめ方: つまみの長さと出し入れの決まりは単体テストで確かめる。見た目は[確かめ専用の窓](index.md#実機の確かめ)で、app のスクロールバーと並べて撮って比べる。

### ローカル画像

整形表示の部品はローカルの画像を表示できない（試験で確認。[mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)）。そのため Markdown 内のローカル画像は、画像の代わりにその名前を押せる形で出し、押すとそのファイルを viewer のタブで開く（viewer は[種類の判定](#種類の判定)のとおりで、画像なら image viewer）。開き方は[リンク](#リンク)と同じ。ローカル画像とは、参照先が `http://`・`https://`・`data:` で始まらないもの。対象にする書き方は次の 3 つ。

- インライン形式: `![図](img/a.png)`
- 参照形式: `![図][arch]`・`![arch][]`・`![arch]` と、その定義 `[arch]: img/a.png`。定義の行は残す（同じ定義を普通のリンクが使っていても壊れない）。
- HTML の `<img src="img/a.png">`。HTML の画像で拾うのは `<img>` だけで、`<picture>` の `<source>` や CSS の背景画像は拾わない。

名前は代替テキスト（`<img>` では `alt`）、無ければファイル名。コードブロック、インラインコード、HTML のコメント（`<!-- -->`）の中は置き換えない。置き換えで行の数が変わっても、Mermaid の図の行番号は元の Markdown で数える（[描けない図](mermaid.md#描けない図)）。

リンクに包まれた画像（`[![図](img/a.png)](docs/a.md)`、`<a href="docs/a.md"><img src="img/a.png"></a>`。部品が描けない http(s) の `<img>` を含む）は、名前を出し、押すと外側のリンク先を[リンク](#リンク)と同じに開く。外側のリンクが同じファイル内の `#見出し` だけ（押しても何もしない種類）なら、画像を開く。

HTML のかたまりの中など、押せる形にできない場所の `<img>`（ローカル、または部品が描けない http(s)）は、「画像: ロゴ（img/logo.png）」のように、画像があったことと場所を押せない文字で出す。

http(s) の画像は、書き方（Markdown か `<img>`）によらず、部品が描けるなら部品に任せ、描けないなら名前を出し、押すとブラウザで開く。

部品が http(s) の画像を描くか、Markdown の中の HTML（`<img>` と `<a>`）をどう描くか、`<a>` を押したことを mod に伝えるかは確かめていない。実装の最初に実機で確かめ、結果を [mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)に書く。どこが押せる形にできない場所か、http(s) の画像を部品に任せるかは、その結果で決まる。`<a>` を押したことが mod に伝わらないと分かった場合は、HTML の `<a>` に包まれた `<img>` も押せる形にできない場所の `<img>` として扱う。

- 成功条件: `![構成図](img/arch.png)` が「構成図」と押せる形で表示され、押すと `img/arch.png` が image viewer のタブで開く。`![構成図][arch]` と `[arch]: img/arch.png`、`<img src="img/arch.png" alt="構成図">` も同じに表示され、同じに開く。`[![構成図](img/arch.png)](docs/arch.md)` の「構成図」を押すと `docs/arch.md` が開く。押せる形にできない場所の `<img src="img/logo.png" alt="ロゴ">` は「画像: ロゴ（img/logo.png）」のように文字で出る。部品が描けない http(s) の画像（Markdown でも `<img>` でも）は名前が出て、押すとブラウザで開く。`[![図](img/a.png)](#top)` の「図」を押すと `img/a.png` が開く。
- 反例: 何も表示されず、画像があったことが分からない（参照形式や `<img>` で）。リンクに包まれた画像で、リンクの記号が文字として残る。コードブロックやコメントの中に書いた例が置き換わる。置き換えで、同じ定義を使う普通のリンクが切れる。
- 確かめ方: 画像を押せる名前にする処理を単体テストで確かめる（3 つの書き方、名前の決め方、コードとコメントの中、共有した定義、リンクに包まれた形（外側が見出しだけのときを含む）、押せない場所の文字、http(s) の画像、置き換えたあとの Mermaid の行番号）。実機で開き、`herdr-app shot` で見て押す。

### 整形の準備

整形表示の部品に渡す前に、画像を押せる名前にし（[ローカル画像](#ローカル画像)）、Mermaid の図を解析・配置して SVG 画像に書き出す（[Mermaid 図](mermaid.md)の[描き方](mermaid.md#描き方)）。これを整形の準備と呼ぶ。整形の準備は mod の中の処理で、描画の中で長く動くと、app が描画を打ち切って整形表示が出なくなる（[mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)の「描画の時間」）。そのため大きな Markdown では、描画の外で整形の準備をする。[整形表示の上限](#整形表示の上限)より小さい Markdown は、画像や図が多くても、整形の準備が原因で整形表示が出なくなることは無い。

描画の中で済ませるか外に出すかは、描画の外で準備する大きさで分ける。値は 2 つで、今の内容の文字数（JavaScript の文字列の長さ）と、` ```mermaid ` の図の数。

- どちらも描画の外で準備する大きさ以下なら、今までどおり描画の中で整形の準備をし、すぐ整形表示する。ただし図の SVG のファイルへの書き出しは描画の中ではできないので、まだ書き出していない図があれば、書き終わるまで今ある待ちの見え方で待つ。開くときと[プレビュータブ](opening-and-tabs.md#プレビュータブ)の中身が入れ替わるときは「読み込み中…」のまま書き終えてから整形表示を出す。ソース表示から戻るとき（ソース表示の間に外から書き換えられたときも）は、書く間「整形中…」を出す（書き出し済みの図だけなら、すぐ整形表示する）。整形表示を出したまま中身が変わったときは、前の整形表示のまま待って差し替える。この書き出しの待ちにも、描画の外の準備の決まり（表示しているときだけ動かす、10 秒の打ち切り、待つ間に中身が変わったときの扱い）を当てる。図の無い文書は書き出しが無いので、すぐ整形表示する。
- どちらかが超えたら（ちょうどは含まない）、描画の外で区切りながら整形の準備をする。整形の準備が終わってから整形表示をまとめて出し、準備していない整形表示を先に出すことはしない。準備が終わるまでの見え方は下のとおり。
- 描画の外で準備する大きさは、画像やバッジ・図の多い Markdown を、大きさを変えて実機で開き、interrupted にならない最大の大きさの半分ほどにする（文字数と図の数のそれぞれ）。図を [SVG 画像で描く](mermaid.md#描き方)作りで測る。測った値は [mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)の「制約」とコードの定数に書き、この仕様には書かない。測ってみて整形表示の上限が描画の外で準備する大きさ以下だったら、描画の外の準備は使われないだけで、この仕様は直さない（そのことを測った値と一緒にガイドに書く）。
- 描画の外の準備は、1 区間を 100 ms ほどまでに区切り、準備の間もスクロールや入力が引っかからないようにする。
- 描画の外の準備は、そのタブを表示しているときだけ動かす。途中でタブを表示しなくなったら止め、戻ったとき中身が同じなら途中から続ける。「整形中…」の間にソース表示へ切り替えても、準備は続ける。
- 整形の準備の結果は、描画の中で一度に準備したときと同じ。
- 図は、その文書の図を全部覚えておき、描き直しのたびに配置し直さない。書き出した SVG も、図の中身と色と書き出しの大きさが変わらない限り書き直さない（[描き方](mermaid.md#描き方)）。

準備が終わるまでの見え方:

- 整形表示に入るとき（開く、ソース表示から戻る、[プレビュータブ](opening-and-tabs.md#プレビュータブ)の中身が入れ替わる）は、今の中身の準備が済んでいればすぐ整形表示を出し、済んでいなければ、整形表示の場所に「整形中…」を出す（進み具合は出さない）。ソース表示で編集してから戻ったときや、ソース表示の間に外から書き換えられてから戻ったときは、前の中身の整形表示は出さない。
- 整形表示を出したまま中身が変わったとき（[外部変更](editing.md#外で書き換えられたら追従する)の読み直し、[下書き](editing.md#下書き)の復元など）は、準備が終わるまで前の整形表示を出し続け、終わったら差し替える。この間だけ、整形表示は今の内容と違う。差し替えでは、スクロールの位置を保つことを目指す（保てるかは実装の最初に確かめ、保てなければ先頭に戻ることを受け入れて、ガイドに書く）。前の整形表示の中の名前・リンク・図を押したら、表示されているとおりの行き先や図を開く。図の拡大の窓が開いていれば、閉じるまで古い図のまま出す。
- 「整形中…」を出している間に中身が変わったら、途中の準備は捨て、今の中身でやり直す。前の整形表示を出している間に中身が変わったら、途中の準備を最後まで続けて差し替え、それから今の中身でやり直す（書き換えが続いても表示が進むように）。どちらでも、「整形中…」から出す結果は今の中身のものだけ。

失敗したとき:

- 画像を押せる名前にする処理が想定していない例外で失敗したら、または図の SVG の最初の書き出しが例外（ファイルに書けないなど）で失敗したら、代わりの整形表示を出し、その上に失敗したこと（「画像を押せる名前にできなかった（理由）」か「図を書き出せなかった（理由）」）を出す。理由は例外のメッセージ。テーマを変えたときの書き出し直しの失敗は、代わりの整形表示にしない（[色](mermaid.md#色)）。
- 描画の外の準備が 10 秒たっても終わらなかったら（準備を動かしている間の時間で数え、タブを表示していなくて止めている間は数えない）、代わりの整形表示を出し、整形の準備が終わらなかったと知らせる。
- 代わりの整形表示では、整形の準備を何もしない。画像は押せる名前にせず、` ```mermaid ` のブロックも図にせずコードのまま出す（図の配置が重さの原因でも、代わりの整形表示が止まらないように）。
- これらの知らせは知らせるだけのもので（並べ方は[ほかの知らせが出ているとき](editing.md#ほかの知らせが出ているとき)）、整形表示のときだけ出し、閉じられない。次の整形の準備が失敗せずに終わるか、タブを閉じたら消える。
- 図の解析や配置の失敗は、今までどおり図ごとに出す（[描けない図](mermaid.md#描けない図)）。

- 成功条件: 整形表示の上限より小さく、描画の外で準備する大きさより大きい、画像やバッジの多い README を開くと、「整形中…」が出たあと整形表示が出て、画像の名前を押すと画像が開く。準備の間もスクロールが引っかからない。描画の外で準備する大きさより小さい README は、図があっても「整形中…」を経ずに出る。図の多い Markdown（部品で描く作りで覚えておけた 64 個を超える図があり、整形表示の上限より小さいもの）も整形表示が出る。整形表示を開いたままその README を外から書き換えると、前の整形表示が出たまま差し替わる。2 秒おきに書き換え続けても、表示が新しい中身に進む。
- 反例: 「This view could not be re-rendered」と「interrupted」が出て、「読み込み中…」のまま進まない（今の症状）。「整形中…」のまま進まない。ふつうの README を開くたびに「整形中…」がちらつく。外から書き換えるたびに「整形中…」に戻る。ソース表示で直して戻ったとき、直す前の中身が見える。
- 確かめ方: 区切りながら準備した結果が描画の中で一度に準備した結果と同じこと、「整形中…」から出す結果が今の中身のものだけであること、前の整形表示を出している間の差し替えの順、描画の外で準備する大きさの判定、10 秒で失敗とする扱い（止めている間は数えないこと）、代わりの整形表示で図をコードのまま出すことは単体テストで確かめる。画像やバッジの多い大きな README、図の多い Markdown、図のある小さな README、ふつうの README を[確かめ専用の窓](index.md#実機の確かめ)で開き、`herdr-app shot` で見る。

## image viewer

最初は枠に収まる大きさで表示する。次の操作を持つ。

- ズーム: ボタンと ctrl+ホイール
- ドラッグで表示位置を移動
- 「等倍」「収まる大きさ」に戻すボタン

画像のピクセル寸法とファイルサイズを表示する。

表示のために、画像を app home 直下の `file-viewer-cache/` にコピーする（[mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)）。ファイルの内容が変わったら新しい名前でコピーし直し、古いコピーは消す。タブを閉じたらそのコピーを消す。アプリの起動後に最初の viewer のタブが動き出したとき、どの viewer のタブも使っていないコピーを消す。

- 成功条件: 大きなスクリーンショットを開くと全体が収まって見え、ctrl+ホイールで拡大してドラッグで細部を見られる。タブを閉じると `file-viewer-cache/` からそのコピーが消える。
- 反例: 等倍で表示されて全体が見えない。`file-viewer-cache/` にコピーが溜まり続ける。
- 確かめ方: 実機で操作し、`herdr-app shot` と `file-viewer-cache/` の中身を見る。

### SVG

SVG は画像として表示し、ボタンでソース表示（code viewer）に切り替えられる。編集はソース表示で行い、保存すると画像表示にも反映される。上限は画像と同じ 6,000,000 バイト。1 MiB を超える SVG はソース表示のボタンを出さず、ソースを表示できない理由を出す。

- 成功条件: `icon.svg` が画像で表示され、ソース表示で色を書き換えて保存すると、画像表示の色が変わる。
- 反例: SVG が code viewer でしか開けない。
- 確かめ方: 実機で操作し、`herdr-app shot` で見る。

## 開けないファイル

バイナリ（NUL を含む）、上限超え、読み込みの失敗のときは、内容の代わりに「なぜ表示できないか」を出す。ファイルのパスと大きさも出す。

- 成功条件: NUL を含む `a.bin` を開くと「バイナリのため表示できない」とパス・大きさが出る。
- 反例: バイナリの中身が文字の羅列として表示される。
- 確かめ方: 実機で開き、`herdr-app shot` で見る。

## 見送った案

- Markdown の既定をソース表示にする / ソースと整形表示を左右に並べる — 読むたびに切り替えるか、幅が半分になる
- リンク・画像を部品の標準動作に任せる — 相対リンクを辿れず、ローカル画像も出ない（試験で確認）
- 画像は「収まる」「等倍」の切り替えだけ — 細部を拡大して見られない
- ファイル内検索を自作してでも入れる — ヒット箇所への移動ができない可能性が高い
- 中身を見て種類を判定する — 判定のために毎回先頭を読む
- 上限を超えたテキストの先頭だけ表示する — 部分表示中は編集できない状態を作る必要がある
- フォルダへのリンクで Files のツリーにそのフォルダを開く — viewer から file-tree への伝え方を新しく作ることになり、範囲が広がる
- フォルダへのリンクも「ファイルが無い」と知らせる — あるものを無いと言って混乱させる
- ローカル画像はインライン形式だけ / 参照形式だけ足して `<img>` は拾わない — 参照形式や README によくある `<img>` の画像に気付けない
- リンクに包まれた画像を押したら画像を開く — 書いた人がつないだリンク先に行けなくなる
- リンクに包まれた画像に、リンク先へ行く印を別に添える — 元の文章に無い印が増える
- 押せる形にできない `<img>` は置き換えない — 画像があったことが分からない
- http(s) の `<img>` をいつも部品に任せる — 部品が描けないと何も出ない
- Markdown の http(s) の画像は表示される前提のまま — 確かめた記録が無く、描けなければ何も出ない
- 外側のリンクが見出しだけのとき、名前を押しても何もしない — その画像をツリーからしか開けない
- `<picture>` の `<source>` も拾う — 同じ画像の別の大きさが名前でいくつも並びうる
- `<img>` の名前をいつも `src` のファイル名にする — 書いた人が付けた説明が出ない
- 整形表示に、部品の重さと関係の無い小さな上限を設けて超えたらソース表示で開く（整形の準備を外に出さずに済ませる） — 部品が描ける大きさまでは、整形の準備のせいで整形表示を諦めない
- 整形の準備をしていない整形表示を先に出し、終わったら差し替える — 準備前の表示（画像の名前が押せず、図がコードのまま）を見せてしまう
- どの Markdown も描画の外で整形の準備をする — ふつうの README で開くたびに「整形中…」がちらつく
- 整形表示を開いたまま中身が変わったら「整形中…」に戻す — 大きな文書を外から書き換えるたびに先頭に戻る
- 部品が固まっても整形表示する / 注意を出したうえで整形表示に切り替えられる — app 全体が固まる時間ができる
- 部品が重すぎるとみなす目安を 3 秒にする — 開いたあと数秒固まることを許してしまう
- 整形の準備の進み具合を出す — 数える処理と途中の描き直しが要る
- 図の多い Markdown は別の件にする — 整形表示の上限より小さいのに整形表示が出ない場合が残る
- 分かれ目を文字数だけで測る — 図の多い小さな文書が描画の中で止まりうる
- ソース表示から整形表示に戻ったとき、編集する前の整形表示を出す — 自分の編集が入っていない中身が見えて戸惑う
- 整形の準備が失敗したらソース表示にする — 本文を整形表示で読めなくなる
- 表示していないタブでも、読み込んだらすぐ整形の準備をする — 表示しないタブの分まで手間がかかる
- 確かめるのは実機だけ — 結果が同じかを機械で確かめられない
- 測った分かれ目の値を、短い壁打ちで仕様に書き足す — 実装の途中で止まり、壁打ちを挟む
- 中身が変わる場面ごとの表で見え方を決める — 場面が見つかるたびに表が増え、抜けが残りやすい
- 前の整形表示を出している間も、中身が変わったら途中の準備を捨てる — 書き換えが続く間、表示が古いまま進まない
- 例外を出さずに終わらない準備を扱わない — 「整形中…」のまま固まり、気付けない
- 失敗したときの代わりの整形表示でも図は配置する — 図の配置が原因の失敗では、代わりの整形表示もまた止まりうる
- 差し替えでスクロールの位置を保つことを必ずの要件にする — 部品で保てないと作りが大きくなる
- 整形表示の上限をバイトだけで決める — 図の多い文書が描画のたびに重くなりうる
- 上限を下回ったら自動で整形表示に戻す — 編集の途中で画面が整形表示に切り替わる
- 描画の外の準備の 1 区間に条件を付けない — 準備の間、数百 ms ずつ app が引っかかりうる
- 図のある小さな文書は、整形表示をすぐ出し、まだ書き出していない図の所を同じ大きさの空きで待つ — 準備の途中の空きを見せてしまう
- 図のある文書は、大きさによらず「整形中…」を経る — 図のある README を開くたびに「整形中…」がちらつく
- 上限の値を、作業者の画面を OS で撮って測る — 測るたびに作業者の PC が使えなくなる
- 作業者の窓で `herdr-app shot` だけを使って測る — 確かめの間、作業者の表示が切り替わり、mod の入れ直しで作業者の app のメモリが減る

## 任せたこと

- 押せない画像の文字や、フォルダへのリンクの知らせの細かい文言（名前の決め方は[ローカル画像](#ローカル画像)で決まっている）。伝える中身は決まっていて、文言で振る舞いは変わらないため。
- 描画の外で[整形の準備](#整形の準備)を区切る方法（入出力の `await` で区切るなど、[mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)の「長い同期処理」に従う）。1 区間が 100 ms ほどまでなら、どの方法でも決めた見え方は変わらないため。
- 整形表示をしない理由と、整形の準備が失敗した・終わらなかった知らせの細かい文言。伝える中身は決まっていて、文言で振る舞いは変わらないため。
- 図を全部覚えておく方法（覚える数の上限の変え方）。その文書の図を全部覚えられれば、決めた見え方は変わらないため。
