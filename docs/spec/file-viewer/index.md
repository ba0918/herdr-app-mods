# File viewer 仕様

herdr-app の Files パネルでファイルを押すと、メイン領域にタブを開き、内容に合った viewer（code / markdown / image）で表示・編集できるようにする。その仕様の入口。

## 構成

- [開き方とタブ](opening-and-tabs.md) — Files ツリーからの開き方、プレビュータブ、タブ名と位置、再起動後の復元、ツリーの表示元
- [viewer](viewers.md) — 種類の判定、code / markdown / image / SVG / 開けないファイル、上限
- [Mermaid 図](mermaid.md) — Markdown 内と .mmd の図の描画、描けない図の扱い
- [編集・保存と外部変更](editing.md) — 編集と保存、保存前の確認、下書き、外で書き換えられたときの追従、文字コードと改行

用語は [CONTEXT.md](../../../CONTEXT.md) にある。プラットフォーム（herdr-app の mod）の事実と制約は [mod 開発ガイド](../../guides/herdr-app-mod-development.md) にある。

## 共通の前提

- 作るものは 3 つの mod と 1 つの layout。viewer の mod は `file-viewer`、ツリーの mod は `file-tree`、`file-viewer` の[付き添いの mod](../../../CONTEXT.md#付き添いの-mod)は `file-viewer-images`、layout は `main-viewer`。
- 利用者は layout の切り替え（`ctrl-shift-l` か設定画面）で `main-viewer` を選んで使う。mod を置いただけでは画面は切り替えない。
- `file-tree` は同梱 `files` を `mod.clone` で複製して作る。`main-viewer` は同梱 `main` を `layout.clone` で複製し、右パネルの `files` ブロックの `content.mod` だけを `file-tree` に差し替える。ブロック id `files` は変えない（同梱タブバーのボタンが id で切り替えるため）。
- space の machine に従って動く（その machine 上でファイルを読み書きし、コマンドを実行する）。実機での確認は machine `wsl` の space で行う。この Windows のローカル space や ssh のリモート space は、同じ作りで動く見込みだが確認しない。

## 実機の確かめ

実機での確認と値の測定は、確かめ専用の herdr-app の窓で行い、作業者の画面・マウス・キーボードは使わない。

- 確かめ専用の窓は、別の app home（環境変数 `HERDR_APP_HOME`）を指定して起動する herdr-app。mod・layout・設定と、mod がタブごとに覚えるもの（viewer の表示の切り替えなど）は作業者の app と別で、確かめる mod はそこにだけ入れる（作業者の app の mod は入れ直さない）。スペース・タブ・端末は herdr-core を通して作業者の窓と共有されるので、確かめのタブは machine `wsl` の確かめ専用のスペースに開き、終わったらそのスペースを閉じる（作業者の窓のスペースの一覧に、その間だけ確かめ専用のスペースが並ぶ）。
- 確かめ専用の窓は前面を取らないまま画面の外に置き、最小化しない（最小化すると描かなくなる）。操作はその窓にだけ送り（PostMessage）、画面は `herdr-app shot` で撮る（隠れていても今の画面が撮れる）。
- 起動の瞬間は前面を取りうるので、確かめ専用の窓の起動は作業者の許可を得たときだけにし、起動したら確かめが終わるまで閉じない。再起動が要る確かめ（[再起動後の復元](opening-and-tabs.md#再起動後の復元)など）は、そのたびに作業者の許可を得て閉じ、起動し直す。確かめの操作の前後で、作業者の窓の表示（選んでいるスペースとタブ）と前面が変わっていないことを見て、変わっていたらやめる。
- 手順の細かいところ（窓の動かし方、操作の送り方）は [mod 開発ガイド](../../guides/herdr-app-mod-development.md)に書く。

- 成功条件: 確かめや測定の間、作業者は自分の PC を普通に使え、作業者の herdr-app で選んでいるスペースとタブ、開いている表示、前面の窓は、作業者の操作でしか変わらない（スペースの一覧に確かめ専用のスペースが並ぶことは除く）。
- 反例: 確かめのたびに作業者の herdr-app を前面にして放置してもらう。確かめのために作業者の窓のタブが切り替わる。作業者の app に確かめ用の mod を入れ直す。
- 確かめ方: 確かめの記録（操作の前後の作業者の窓の `herdr-app status` と前面の窓）を人が読む。

## 画像の置き場所

[image viewer](viewers.md#image-viewer) の画像のコピーと、[Mermaid 図の SVG](mermaid.md#描き方)（まとめて「絵のファイル」）は、[付き添いの mod](../../../CONTEXT.md#付き添いの-mod) `file-viewer-images` のフォルダ（app home の `mods/file-viewer-images/`）に置き、使わなくなった絵は[手放す](../../../CONTEXT.md#手放す)。app は読み込んだ画像をパスごとに覚え、タブを閉じてもファイルを消しても放さず、`mods/` の下のアセットが書き換えられたときだけ取り直して前の絵を放す（[mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)の「image(path) の読み込み」「image(path) のメモリ」）。

付き添いの mod:

- 付き添いの mod は、何も描かない `main.js` と、どこにも出さない `mod.json` を持つ mod。`file-viewer` と一緒に、同じ入れ方（リポジトリの入れる手順）で入れる。入れ直すときは `main.js` と `mod.json` だけを書き、中の絵のファイルと app が書くファイル（型定義など）は消さない。
- `mods/file-viewer-images/` に `main.js` と `mod.json` があることを、絵のファイルを書く前に毎回確かめる。無ければ書かず、図は[描けない図](mermaid.md#描けない図)（理由: 付き添いの mod が入っていない）、画像は[開けないファイル](viewers.md#開けないファイル)（理由: 付き添いの mod が入っていない）として出す。絵を書く場面では、この判定を書き出しの失敗・整形の準備の失敗・色の書き出しの失敗より先にする（付き添いの mod が無いだけなら、代わりの整形表示にしない）。未対応の種類や文法エラーなど、書き出す前に決まる描けない図の理由はそのまま出す。入れたら、次に書き出すときから普通に出す。`file-viewer` は付き添いの mod を作らない。
- 使っている途中で付き添いの mod が外されたら、表示中の絵はそのまま出し、新しく書く絵から上の見え方にする。それまでの絵は、app を再起動するまで手放せない。

名前と手放す時:

- 絵のファイルの名前はタブごとに分け（タブの印を入れる）、書き出すたびに新しい番号を入れる。手放した名前は使い直さない（前のテーマや倍率に戻したら、新しい名前で書き出し直す）。あるタブが手放しても、ほかのタブの絵は替わらない。
- 絵のファイルを使う場所（画面に出している所と、見えない所で読み込ませている所）が 1 つも無くなったら、その絵を手放してから消す。同じタブの中で 2 か所が同じファイルを使っているときは、両方が使わなくなるまで手放さない。使わなくなる例: 新しい絵が出た（図の中身・テーマ・倍率・本文の幅に合わせて縮めた大きさが変わった、プレビュータブで別のファイルに替わった、画像の中身が変わった）、図を消した、図が描けない図や代わりの整形表示になった、[整形表示の上限](viewers.md#整形表示の上限)でソース表示に移った、続けて倍率を変えて途中の絵が要らなくなった。
- 新しい絵に替えるときは、新しい絵の読み込みが終わって画面で差し替えてから、前の絵を手放す（図が一瞬空かないように）。書き出し中のファイルは、書き終わってから手放す。
- [拡大の窓](mermaid.md#拡大表示)は、今出している絵（本文の絵を借りているときも）を、本文が使わなくなっても持つ。窓の中で倍率や色を替えて差し替えたら、窓だけが使っていた前の絵を手放す。窓を閉じたら、窓だけが使っていた絵を手放す。
- 表示していないタブも、閉じるまでは今出している絵を持つ。Markdown と `.mmd` でソース表示に切り替えている間も、整形表示で出していた絵を持つ（戻ったとき、中身が同じならすぐ出す）。

片付け:

- タブを閉じるとき（`close` が呼ばれれば）、そのタブの絵を手放し始める。`close` は呼ばれないことや途中で終わることがあるので、片付けを保証するのは見張り。
- `file-viewer` のどのタブも、表示していなくても、2 秒おきに見張る。見張りは、開いているタブ（タブの記録のうち、今ある viewer のペインに結びついているものと、開いたばかりで名乗り待ちのもの。記録の印は再起動しても同じ印で復元される）のどれの印でもない絵のファイルのうち、書いてから 10 秒以上たったものを、手放してから消す。タブは絵を書く前に自分の印を記録に載せる。再起動で復元したタブは、自分の印の絵のファイルで今使っていないものを自分で手放して消す。ほかに `file-viewer` のタブが無ければ、次に開いたタブ（復元したタブを含む）がする。
- 前の置き場所（app home 直下の `file-viewer-cache/`）は、`file-viewer` のタブが最初に見張るときに、名前の形が `file-viewer` のものであるファイルを消し、空ならフォルダも消す（`mods/` の外なので、消すだけで手放しはできない）。
- 手放されることは app の説明に書いてなく、測った事実に頼る。app の版が上がったら、下の確かめ方で測り直す。

- 成功条件: [確かめ専用の窓](#実機の確かめ)の herdr-app のプロセスの private bytes を、全部の viewer のタブを閉じた状態から始め、最後の操作から 5 秒後に測る。(1) 図 40 個の Markdown をプレビュータブで別のファイルと交互に 5 回開き替えて閉じる、(2) その Markdown を開いてテーマを 3 回行き来して閉じる、(3) 拡大の窓と `.mmd` で倍率を上げ下げして閉じる、(4) 図のある Markdown を 2 つのタブで開き、裏のタブを閉じてから残りも閉じる、のどれでも、始めと終わりの差が 50 MiB 以下。直す前の作り（名前にタブの印を入れて `file-viewer-cache/` に置く作り）では同じ手順が 50 MiB を大きく超える。(5) 確かめ専用の窓を強制終了して起動し直し、`file-viewer` のタブを開いて 5 秒後、`mods/file-viewer-images/` には `main.js`・`mod.json`・app が書くファイルと、開いているタブが使う絵のファイルしか無い。どの手順のあとも、図と画像は正しい絵で出て、ほかのタブの絵は替わっていない。付き添いの mod を外して開くと、図は描けない図、画像は開けないファイルとして、理由「付き添いの mod が入っていない」が出る。
- 反例: 開き直すたびに app のメモリが増え、タブを閉じても戻らない。あるタブが手放したら、別のタブや同じタブの別の場所の絵が小さい絵に替わる。図が一瞬空いてから替わる。`mods/file-viewer-images/` に絵のファイルが溜まり続ける。付き添いの mod への書き込みで `file-viewer` が読み直され、タブの状態（スクロールの位置など）が消える。付き添いの mod を入れ直すと、表示中の図が空く。
- 確かめ方: 名前の決め方、手放す絵と片付けるファイルを選ぶ処理、付き添いの mod があるかの判定は単体テストで確かめる。メモリは確かめ専用の窓で、app のプロセスの private bytes を外から測る（mod からは読めない。図の大きさや倍率の回数などの細かい手順は、実装のときに [mod 開発ガイド](../../guides/herdr-app-mod-development.md)に書く）。各手順のあと `herdr-app shot` で絵とタブの状態を見て、`mods/file-viewer-images/` の中身の一覧を見る。表示中に付き添いの mod を入れ直して撮る。

## 作らないもの

- Files ツリー自体の強化（検索、件数上限の緩和、アイコン、開いているファイルをツリーで選択状態にする機能など）。別の仕様で扱う。
- PDF・CSV 表・動画などの viewer。
- Files ツリーと Markdown 内リンク以外の入口（パス入力ダイアログ、キー割り当て、ターミナルに出たパスを開くなど）。
- 開けないファイルを既定のアプリで開くボタン。
- UTF-8 以外の文字コードの編集。
- Mermaid の flowchart / sequenceDiagram 以外の図。
- Markdown 内の `<img>` 以外の HTML の画像（`<picture>` の `<source>`、CSS の背景画像）を押せる名前にすること。
- Markdown 内のフォルダへのリンクから、Files のツリーでそのフォルダを開くこと。

## 任せたこと

- viewer 内のボタンやツールバーの並べ方。決めた操作が全部ある限り、並べ方で振る舞いは変わらないため。テーマ色を使い、同梱 mod の見た目に揃える。
- Mermaid の配置計算の方法と、同梱ライブラリの選定（[同梱してよいライブラリ](mermaid.md#同梱してよいライブラリ)の条件内。描き方は [SVG 画像](mermaid.md#描き方)と決めてある）。どの方法でも、決めた見た目と振る舞いは変わらないため。

## 見送った案

- space ごとの Viewer タブの中に自前のファイルタブ列を持つ — タブの並び・閉じる・復元を mod 内で作り直すことになる
- ターミナルの横にペインとして開く — 開くたびにターミナルが狭くなる
- CSV 表・JSON 整形なども最初から / code と markdown だけ先に — 最初の版が大きくなる / 依頼にあった画像が開けない
- ツリーも作り直して今回含める — 決めることと作る量が倍近くになる
- WSL の space だけに絞る — 他の machine の space で使えなくなる
- 参照だけで先に出す — 保存の試験が通った
- パス入力ダイアログとキー割り当て / 既定のアプリで開くボタン — 今回は入口と範囲を絞る
- 画像と図の絵を app home 直下の `file-viewer-cache/` に置いたまま、名前の使い回しで増え方を小さくする — 書き換えても絵が手放されず、一度出した絵の分が再起動まで残る（測った）
- 絵を `mods/file-viewer/` の中に置く — 書き換えるたびに `file-viewer` が読み直され、タブの状態が消える（測った）
- 絵を `mods/` の下の、`main.js` の無いフォルダに置く — app の説明に無い振る舞いに頼る分、付き添いの mod より壊れやすい
- 見えている図だけを部品で描き、画像を使わない — 部品で描いていた作りの問題が戻りうるうえに、作り直しが大きい。付き添いの mod で手放せなくなったときの逃げ道として残す
- タブを閉じるまで絵を持っておく / 裏に回ったタブの絵を手放す — 拡大やテーマの行き来で閉じるまで増え続ける / 戻るたびに「整形中…」の待ちがある
- 付き添いの mod が無ければ `file-viewer` が作る / 前の置き場所に戻して描く — mod が知らないうちに別の mod を作る / その間は開くたびにメモリが増える
- 次に `file-viewer` のタブを開いたときだけ片付ける — ほかの `file-viewer` のタブがあっても、閉じたタブの分がすぐには戻らない
- 付き添いの mod をフォルダごと入れ替える — 入れ直すと表示中の図が消え、手放されないまま絵の場所が空く
- 手放されることを受け入れのときだけ測る — app の版が上がって手放されなくなっても気づけない
- ソース表示に切り替えたら整形表示の絵を手放す — 戻るたびに書き出し直しの待ちがある
- 手放した絵に戻るとき同じ名前に書き直す — 取り直しより先に、覚えていた小さい絵が一瞬見えるかもしれない（確かめていない）
- 見張りが herdr のタブの一覧だけで持ち主の無いファイルを決める（タブの記録と、書いてからの時間を見ない） — 開いたばかりで、まだ一覧に載っていないタブの絵を取り違える

## 決めていないこと

- app に、画像を手放す手段かバイト列から画像を出す手段を足してもらうよう、作者に頼むか（付き添いの mod に頼らない本来の直し方）。決めるのは作業者。
