# File viewer 仕様

herdr-app の Files パネルでファイルを押すと、メイン領域にタブを開き、内容に合った viewer（code / markdown / image）で表示・編集できるようにする。その仕様の入口。

## 構成

- [開き方とタブ](opening-and-tabs.md) — Files ツリーからの開き方、プレビュータブ、タブ名と位置、再起動後の復元、ツリーの表示元
- [viewer](viewers.md) — 種類の判定、code / markdown / image / SVG / 開けないファイル、上限
- [Mermaid 図](mermaid.md) — Markdown 内と .mmd の図の描画、描けない図の扱い
- [編集・保存と外部変更](editing.md) — 編集と保存、保存前の確認、下書き、外で書き換えられたときの追従、文字コードと改行

用語は [CONTEXT.md](../../../CONTEXT.md) にある。プラットフォーム（herdr-app の mod）の事実と制約は [mod 開発ガイド](../../guides/herdr-app-mod-development.md) にある。

## 共通の前提

- 作るものは 2 つの mod と 1 つの layout。viewer の mod は `file-viewer`、ツリーの mod は `file-tree`、layout は `main-viewer`。`file-viewer` は絵を置くフォルダ `mods/file-viewer-images/`（[画像の置き場所](#画像の置き場所)。mod ではない）と、一時ファイルを置くフォルダ `file-viewer-read/`（[一時ファイル](#一時ファイル)）を自分で作る。
- 利用者は layout の切り替え（`ctrl-shift-l` か設定画面）で `main-viewer` を選んで使う。mod を置いただけでは画面は切り替えない。
- `file-tree` は同梱 `files` を `mod.clone` で複製して作る。`main-viewer` は同梱 `main` を `layout.clone` で複製し、右パネルの `files` ブロックの `content.mod` だけを `file-tree` に差し替える。ブロック id `files` は変えない（同梱タブバーのボタンが id で切り替えるため）。
- space の machine に従って動く（その machine 上でファイルを読み書きし、コマンドを実行する）。実機での確認は machine `wsl` の space で行う。この Windows のローカル space や ssh のリモート space は、同じ作りで動く見込みだが確認しない。

## 実機の確かめ

実機での確認と値の測定は、確かめ専用の herdr-app の窓で行い、作業者の画面・マウス・キーボードは使わない。

- 確かめ専用の窓は、別の app home（環境変数 `HERDR_APP_HOME`）を指定して起動する herdr-app。mod・layout・設定と、mod がタブごとに覚えるもの（viewer の表示の切り替えなど）は作業者の app と別で、確かめる mod はそこにだけ入れる（作業者の app の mod は入れ直さない）。スペース・タブ・端末は herdr-core を通して作業者の窓と共有されるので、確かめのタブは machine `wsl` の確かめ専用のスペースに開き、終わったらそのスペースを閉じる（作業者の窓のスペースの一覧に、その間だけ確かめ専用のスペースが並ぶ）。
- 確かめ専用の窓は前面を取らないまま画面の外に置き、最小化しない（最小化すると描かなくなる）。操作はその窓にだけ送り（PostMessage）、画面は `herdr-app shot` で撮る（隠れていても今の画面が撮れる）。一瞬の空白を見るときは、その窓だけを PrintWindow で続けて撮る（前面と作業者の画面は変えない）。
- 起動の瞬間は前面を取りうるので、確かめ専用の窓の起動は作業者の許可を得たときだけにし、起動したら確かめが終わるまで閉じない。再起動が要る確かめ（[再起動後の復元](opening-and-tabs.md#再起動後の復元)など）は、そのたびに作業者の許可を得て閉じ、起動し直す。確かめの操作の前後で、作業者の窓の表示（選んでいるスペースとタブ）と前面が変わっていないことを見て、変わっていたらやめる。
- 手順の細かいところ（窓の動かし方、操作の送り方）は [mod 開発ガイド](../../guides/herdr-app-mod-development.md)に書く。

- 成功条件: 確かめや測定の間、作業者は自分の PC を普通に使え、作業者の herdr-app で選んでいるスペースとタブ、開いている表示、前面の窓は、作業者の操作でしか変わらない（スペースの一覧に確かめ専用のスペースが並ぶことは除く）。
- 反例: 確かめのたびに作業者の herdr-app を前面にして放置してもらう。確かめのために作業者の窓のタブが切り替わる。作業者の app に確かめ用の mod を入れ直す。
- 確かめ方: 確かめの記録（操作の前後の作業者の窓の `herdr-app status` と前面の窓）を人が読む。

## 画像の置き場所

[image viewer](viewers.md#image-viewer) の画像のコピーと、[Mermaid 図の SVG](mermaid.md#描き方)（まとめて「絵」）は、app home の `mods/file-viewer-images/` に置いた[絵の席](../../../CONTEXT.md#絵の席)のファイルに書き、使わなくなった絵は[手放す](../../../CONTEXT.md#手放す)。この決まりは app の次の振る舞いに頼る（[mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)の「`image(path)` の絵の覚え方」「app home の見張り」「フォルダの変化の知らせ」「消してから手放されるまで」。ソースと playground の測定による）。

- app は読み込んだ絵をパスごとに覚え、`mods/` の下のそのファイルに変化の知らせが来たら捨てる。
- それとは別に、どの窓も描いていない読み込み済みの絵（使っていない絵）は、最近使った順に 128 MiB・128 個までを残し、大きさか数のどちらかを超えた分を、古いものから捨てる。読み込みに失敗した絵はすぐ捨てる。捨てた絵は、次に描くときにファイルから読み直す（読み直す間は空白になりうる）。
- 使っていない絵が 128 MiB まで残るので、この捨て方は手放しの代わりにならない。下の絵の席と手放しの決まりはこの捨て方があっても変えず、この捨て方は、手放しが漏れたときにメモリに残る絵の上限として働く。
- フォルダの中でファイルやフォルダを作る・消すと、そのフォルダの下から出している絵が全部捨てられて読み直され、その間は一瞬空白になる。`mods/` のすぐ下でフォルダを作る・消すと、ほかの mod の絵も含めて `mods/` の下の絵が全部そうなる。同じ名前のファイルを上書きするだけなら、捨てられるのはその絵だけで、隣の絵は空白にならない。
- 絵の形式は中身で決まり、ファイル名の拡張子は見ない。

置き場所と絵の席:

- `mods/file-viewer-images/` は `main.js` の無いただのフォルダで、mod ではない。`file-viewer` が絵を書くときに無ければ作る（このとき一度、`mods/` の下のほかの mod の絵も一瞬空白になる。ほかの mod は読み直されない）。
- 絵の席は、前もって作っておく決まった名前のファイル。使うときは新しい絵で上書きし、手放すときはごく小さい絵（1 × 1 px）で上書きする。手放した絵の席は、次の絵に使い直す。
- ファイルを作る・消すのは、そのとき出している絵が一瞬空白になっても困らない、まれな場面だけにする: フォルダを初めて作るとき、絵の席が足りなくなってまとめて増やすとき、外から消されたフォルダや絵の席のファイルを作り直すとき。それ以外の、テーマ・倍率・本文の幅を替えて書き出し直すとき、タブやプレビュー・拡大の窓を開く・閉じるとき、画像の中身が変わったときは、上書きだけで書き出しと手放しをする。
- 初めに作る絵の席は、次を増やさずにできる数以上にする: [整形表示の上限](viewers.md#整形表示の上限)ちょうどの図の数の Markdown（どの図もタイルに分かれない大きさ）を 1 つ開き、テーマを 1 回替え、その図の 1 つを拡大の窓で開いて倍率を 1 回替え、image viewer で SVG（タイルに分かれない大きさ）を 1 つ開いて倍率を 1 回替える（差し替えの間は前と新しい絵の席を両方使うことを含む）。
- 絵の席は減らさない。使っていない絵の席は、ごく小さい絵のファイルとして残る。
- 窓が違えば app home も違う（同じ app home の herdr-app は 1 つの窓だけを開く）ので、絵の席は窓ごとに分かれる。

絵の席の表:

- どの絵の席をどこが使っているかは、窓の `globalThis` に `file-viewer` だけが使う名前で置いた表で覚える。表は、コピーの `init` で無ければ作る（モジュールの読み込みでは作らない）。タブの記録（`shared.json`）には書かない。表は、同じ窓の `file-viewer` のタブと[拡大の窓](mermaid.md#拡大表示)の全部が使う（モジュールの変数は、初めて開いたときや `mods/` のすぐ下のフォルダを作る・消したあとに、同じ mod のコピーで分かれることがあるので使わない）。
- 同じ中身・同じ色・同じ大きさの図や画像は、1 つの絵の席を共有する。絵の席を使う場所（画面に出している所と、見えない所で読み込ませている所）を、タブと拡大の窓をまたいで数え、全部が使わなくなったら手放す。拡大の窓の使う場所は、窓を開いたタブの印（タブの記録の印。再起動しても同じ印で戻る）に結びつける。
- 使う場所は、タブの印と、本文か拡大の窓かで見分ける。同じタブの印のコピーが init し直したら（hot reload など）、本文のコピーは本文の使う場所を、拡大の窓のコピーは窓の使う場所を、それぞれ引き継ぐ。
- 起動し直すと、表はまだ無い。その起動で初めて表を作るときに、フォルダの一覧から全部の絵の席を見つけ、ごく小さい絵で上書きして手放す。表示していない復元タブの前の絵もこのとき小さくなり、そのタブは表示したときに書き直す。
- フォルダか絵の席のファイルが外から消されたら（見張りの回で気づく）、フォルダと、消えた絵の席のファイルを同じ名前で作り直す。表はそのまま使う。消えた絵の席を使っていたタブと拡大の窓は、出していた絵をその絵の席に書き直す。どこも使っていなかった絵の席は、ごく小さい絵で作る。書き直すまでの間、その絵は空白になりうる。

手放す時:

- 手放すのは、出していない絵の席だけ（出したまま 1 × 1 で上書きすると、メモリが減るのが 40 秒あまり遅れたことがある。ガイドの「フォルダの変化の知らせ」）。
- 新しい絵に替えるときは、同じ見た目の絵の席があればそれを共有し、無ければ使っていない絵の席に新しい絵を書き、見えない所で読み込ませ、読み込みが終わってから画面で差し替える。差し替えた前の絵の席は、それを使わない描画が済んだことを描画の回数で確かめてから手放す（図が一瞬空白にならないように）。そのタブを表示していない間は、描画の回数で確かめられないので、差し替えた前の絵の席を手放さない。書き出し中の絵の席は、書き終わってから手放す。使わなくなる例: 新しい絵が出た（図の中身・テーマ・倍率・本文の幅に合わせて縮めた大きさが変わった、プレビュータブで別のファイルに替わった、画像の中身が変わった）、図を消した、図が描けない図や代わりの整形表示になった、[整形表示の上限](viewers.md#整形表示の上限)でソース表示に移った、続けて倍率を変えて途中の絵が要らなくなった。
- [拡大の窓](mermaid.md#拡大表示)は、今出している絵（本文と共有している絵の席も）を、本文が使わなくなっても持つ。窓の中で倍率や色を替えて差し替えたら、窓だけが使っていた前の絵の席を手放す。窓を閉じたら、窓だけが使っていた絵の席を手放す。
- 表示していないタブも、閉じるまでは今出している絵を持つ。Markdown と `.mmd` で利用者がソース表示を選んでいる間も、整形表示で出していた絵を持つ（戻ったとき、中身が同じなら書き出し直さずに出す。app が使っていない絵として捨てていたら、ファイルから読み直す）。その間に中身が変わったら、整形表示に戻って新しい絵に替えたときに手放す（[整形表示の上限](viewers.md#整形表示の上限)を超えたら、そのときに手放す）。

片付け:

- タブを閉じるとき（`close` が呼ばれれば）、そのタブだけが使っていた絵の席を手放す。`close` は、一度も表示していないタブでは呼ばれず、app を終えるときは中の書き込みが終わらない（ガイドの「閉じるときの呼び出し」）ので、片付けを保証するのは見張りと、起動して初めて表を作るときに手放すこと。
- `file-viewer` のどのタブも、表示していなくても、2 秒おきに見張る。見張りは、表のうち、開いているタブ（タブの記録のうち、今ある viewer のペインに結びついているものと、開いたばかりでまだ自分のペインを記録に書いていないもの）の印に結びつかない使う場所を外し、どこも使わなくなった絵の席を手放す。
- 前の置き場所（app home 直下の `file-viewer-cache/`）は、起動して初めて見張るときに、名前の形が `file-viewer` のものであるファイルを消し、空ならフォルダも消す（`mods/` の外なので、消してもメモリは放されない。出している絵はもう無いので、空白になる絵も無い）。
- 手放されることと空白になることは app の説明に書いてなく、ソースと測った事実に頼る。app の版が上がったら、そのタグのソースを読み直し、下の確かめ方で測り直す。

- 成功条件: [確かめ専用の窓](#実機の確かめ)の herdr-app のプロセスの private bytes を、全部の viewer のタブを閉じた状態から始め、最後の操作から 10 秒後に測る。(1) 図 40 個の Markdown をプレビュータブで別のファイルと交互に 5 回開き替えて閉じる、(2) その Markdown を開いてテーマを 3 回行き来して閉じる、(3) 拡大の窓と `.mmd` で倍率を上げ下げして閉じる、(4) 図のある Markdown を 2 つのタブで開き、裏のタブを閉じてから残りも閉じる、のどれでも、始めと終わりの差が 50 MiB 以下。直す前の作り（名前にタブの印を入れて `file-viewer-cache/` に置く作り）では同じ手順が 50 MiB を大きく超える。(5) 確かめ専用の窓を強制終了して起動し直し、`file-viewer` のタブを開いて 10 秒後、`mods/file-viewer-images/` の絵の席のファイルはどれも、開いているタブが出している絵か、ごく小さい絵。(6) 絵の席を増やさない範囲で、次の場面のとき、操作していないほうの絵（図のある Markdown のタブの図と、大きな PNG を開いた image viewer のタブの画像）が一瞬も空白にならない: 同じタブでテーマ・倍率を替える、ほかのタブを開く・閉じる・プレビューを替える、拡大の窓を開く・閉じる。どの手順のあとも、図と画像は正しい絵で出て、ほかのタブの絵は替わっていない。
- 反例: 開き直すたびに app のメモリが増え、タブを閉じても戻らない。あるタブの書き出しや手放しで、別のタブや同じタブの別の場所の図が一瞬空白になる、または小さい絵に替わる。図が一瞬空白になってから替わる。`mods/file-viewer-images/` に大きな絵のファイルが溜まり続ける。絵を書き込むたびに `file-viewer` が読み直され、タブの状態（スクロールの位置など）が消える。
- 確かめ方: 絵の席の表（使い始める・共有して数える・手放す絵の席を選ぶ・本文と窓で分けて引き継ぐ・初めて作るときに手放す・見張りが外す・消えた絵の席を作り直す）は単体テストで確かめる。メモリは確かめ専用の窓で、app のプロセスの private bytes を外から測る（mod からは読めない。細かい手順は [mod 開発ガイド](../../guides/herdr-app-mod-development.md)の「メモリの測り方」）。各手順のあと `herdr-app shot` で絵とタブの状態を見て、`mods/file-viewer-images/` の中身の一覧と大きさを見る。(6) は、絵の席が足りている状態から、確かめ専用の窓を続けて撮り（ガイドの「一瞬の空白の撮り方」。12 ms ほどおき）、場面ごとに 5 回ずつ、操作していないほうの絵に空白のコマが 0 枚であることで確かめる（撮る間隔より短い空白、例えば小さい SVG の 1 コマは見逃しうる）。

## 一時ファイル

`file-viewer` は、次の読み書きの途中で、app home の `file-viewer-read/` に一時ファイルを置く。`mods/` の外に置くのは、`mods/` の下でファイルを作る・消すと、そのフォルダの下から出している絵が一瞬空白になるため（[画像の置き場所](#画像の置き場所)）。

- このコンピュータの 1 MiB を超える SVG の全文を読むとき（[表示の大きさで書き直す](viewers.md#表示の大きさで書き直す)）と、ほかの machine の画像のバイト列を絵の席に書くとき。
- 一時ファイルは 1 回の読み書きごとに新しい名前で作り、その読み書きが終わったら（失敗しても）消す。
- 消す前に app が終わったときなどに残ったものは、起動して初めて見張るとき（[画像の置き場所](#画像の置き場所)の片付けで、前の置き場所を消すのと同じとき）に、`file-viewer-read/` の中のファイルのうち、名前によらず、書いてから 10 分を過ぎたものを消す。使っているかではなく古さで決めるのは、同じ窓のほかのタブが読み書きの最中かもしれないため（使っている一時ファイルは、1 回の読み書きの間しか無い）。

- 成功条件: machine `wsl` の画像を開いて表示したあと、`file-viewer-read/` は空。`file-viewer-read/` に、書いた時刻が 1 時間前のファイルと今のファイルを置いて[確かめ専用の窓](#実機の確かめ)を起動し直し、`file-viewer` のタブを開くと、10 秒後には 1 時間前のファイルが消え、今のファイルは残っている（使っている最中の、書いたばかりの一時ファイルを消さない）。
- 反例: `file-viewer-read/` に一時ファイルが溜まり続ける。ほかのタブが読み書きしている最中の一時ファイルが消されて、その読み込みが失敗する。
- 確かめ方: 確かめ専用の窓で、開く前後と起動し直す前後の `file-viewer-read/` の一覧（名前と書いた時刻）を見る。このコンピュータの 1 MiB を超える SVG を読むときの一時ファイルは、実機で確かめる space（machine `wsl`。[共通の前提](#共通の前提)）では通らないので、実機では確かめない。

## 作らないもの

- Files ツリー自体の強化（検索、件数上限の緩和、アイコン、開いているファイルをツリーで選択状態にする機能など）。別の仕様で扱う。
- PDF・CSV 表・動画などの viewer。
- Files ツリーと Markdown 内リンク以外の入口（パス入力ダイアログ、キー割り当て、ターミナルに出たパスを開くなど）。
- 開けないファイルを既定のアプリで開くボタン。
- UTF-8 以外の文字コードの編集。
- Mermaid の flowchart / sequenceDiagram 以外の図。
- Markdown 内の `<img>` 以外の HTML の画像（`<picture>` の `<source>`、CSS の背景画像）を押せる名前にすること。
- Markdown 内のフォルダへのリンクから、Files のツリーでそのフォルダを開くこと。
- 絵の席を減らすこと（一度作った絵の席は、ごく小さい絵のファイルとして残る）。
- 窓をまたいで絵の席をそろえる仕組み（窓が違えば app home が違うので要らない）。
- 使っている絵の席をタブの記録（`shared.json`）に書くこと。
- `main.js` と `mod.json` を持つ置き場所の mod（前の作り）と、それを入れる手順。
- app の作者に、画像を手放す手段やバイト列から画像を出す手段を足してもらうよう頼むこと（作業者が頼まないと決めた。今の作りはソースと測った事実に頼る）。

## 任せたこと

- 絵の席の初めの数（置き場所と絵の席の下限より多く）と、足りないときに増やす数。下限を守れば、増やすのはまれな場面だけという振る舞いは変わらないため。
- 絵の席のファイルの名前の付け方と、`globalThis` の表の名前。絵の形式は中身で決まり（ソースと測定）、名前は振る舞いに出ないため。ほかの mod とぶつからず、フォルダの一覧から全部の絵の席を見つけられ、見張りが除く名前（ガイドの「app home の見張り」）と「.」で始まる名前を使わない。
- ごく小さい絵（1 × 1 px）の形式。形式をまたいで上書きしても描き直され、1 × 1 の PNG で手放せたため（測った）。
- viewer 内のボタンやツールバーの並べ方。決めた操作が全部ある限り、並べ方で振る舞いは変わらないため。テーマ色を使い、同梱 mod の見た目に揃える。
- Mermaid の配置計算の方法と、同梱ライブラリの選定（[同梱してよいライブラリ](mermaid.md#同梱してよいライブラリ)の条件内。描き方は [SVG 画像](mermaid.md#描き方)と決めてある）。どの方法でも、決めた見た目と振る舞いは変わらないため。

## 見送った案

- space ごとの Viewer タブの中に自前のファイルタブ列を持つ — タブの並び・閉じる・復元を mod 内で作り直すことになる
- ターミナルの横にペインとして開く — 開くたびにターミナルが狭くなる
- CSV 表・JSON 整形なども最初から / code と markdown だけ先に — 最初の版が大きくなる / 依頼にあった画像が開けない
- ツリーも作り直して今回含める — 決めることと作る量が倍近くになる
- WSL の space だけに絞る — 他の machine の space で使えなくなる
- 参照だけで先に出す — 保存の試験が通った
- パス入力ダイアログとキー割り当て / 既定のアプリで開くボタン — 今回は入口と範囲を絞る
- 画像と図の絵を app home 直下の `file-viewer-cache/` に置いたまま、名前の使い回しで増え方を小さくする — 書き換えても app が絵を捨てず、一度出した絵の分が再起動まで残る（0.1.14 で測った。0.1.15 でも、使っていない絵が最大 128 MiB 残る）
- 絵を `mods/file-viewer/` の中に置く — 書き換えるたびに `file-viewer` が読み直され、タブの状態が消える（測った）
- 絵を `mods/` の下の、`main.js` と `mod.json` を持つ置き場所の mod（前の作り）に置き、入れる手順で用意する — `main.js` が無くても絵を捨てる知らせは届き（ソース）、入れる手順と、入っていないときの扱いが要らなくなる
- 見えている図だけを部品で描き、画像を使わない — 部品で描いていた作りの問題が戻りうるうえに、作り直しが大きい。絵の席で手放せなくなったときの逃げ道として残す
- タブを閉じるまで絵を持っておく / 裏に回ったタブの絵を手放す — 拡大やテーマの行き来で閉じるまで増え続ける / 戻るたびに「整形中…」の待ちがある
- 次に `file-viewer` のタブを開いたときだけ片付ける — ほかの `file-viewer` のタブがあっても、閉じたタブの分がすぐには戻らない
- 手放されることを受け入れのときだけ測る — app の版が上がって手放されなくなっても気づけない
- ソース表示に切り替えたら整形表示の絵を手放す — 戻るたびに書き出し直しの待ちがある
- 見張りが herdr のタブの一覧だけで持ち主の無い絵を決める（タブの記録を見ない） — 開いたばかりで、まだ一覧に載っていないタブの絵の席を取り違える
- 絵ごとに新しい名前のファイルを作り、使わなくなったら消す — ファイルを作る・消すたびに、同じフォルダから出している絵が全部一瞬空白になる（測った。大きな PNG で 10 回中 10 回、約 0.1 秒）
- タブを開く・閉じるときにタブごとのフォルダを作る・消す — フォルダを作る・消すと親フォルダの下の絵が全部一瞬空白になるので、ほかのタブの開閉で全部のタブの図が空白になる（測った）
- どの場面でも一瞬空白になるのを許す — 空白が見えて分かったので避ける
- 消すだけで手放す — 消すと同じフォルダから出している絵が全部一瞬空白になる
- 初めに決めた数だけ絵の席を作り、増やさない — 超えた分の図や画像の扱いが要る
- 使っている絵の席をタブの記録（`shared.json`）に書く — 窓の `globalThis` の表で足り、コピーどうしの書き合いをそろえる手間が要らない
- 再起動のあと、表示していない復元タブの前の絵を、そのタブを表示するか閉じるまで残す / 決めた時間のうちにほかのタブが片付ける — 起動して初めて表を作るときに上書きで手放しても、どの絵も空白にならない / 生きているタブを見分ける作りが要る
- 前の絵の席を、決まった時間待ってから手放す — 描画が遅れたときに、まだ出ている絵の席を手放して空白にしうる
- モジュールの変数で表を持つ — 初めて開いたときや `mods/` のすぐ下のフォルダを作る・消したあとに、同じ mod のコピーでモジュールが分かれた（測った）
- app が使っていない絵を捨てるのに任せて、mod の手放し（1 × 1 の絵で上書き）をやめる — タブを閉じたあとも、使っていない絵が最大 128 MiB メモリに残る（使っていない絵が 128 MiB まで残ることは測った）
- メモリの成功条件を測る時を、最後の操作から 30 秒後にする — 戻りが遅くなったことを条件が拾わなくなる

## 決めていないこと

- 整形表示の図は、画面の外にあるものも全部読み込まれてメモリに残る（測った。ガイドの「`image(path)` のメモリ」）。図の多い文書では、整形表示の上限の図の数まで並ぶと数 GiB になりうる（測った 1 個あたりの値からの見積もり）。これをどう抑えるか。決めるのは作業者（続く別の検討で）。
- 成功条件 (1) の手順を続けて 18 回繰り返すと、閉じて 10 秒後の値が始めより 50 MiB を超えて高い回があり（18 回中 2 回。どれも次の回を始めるまでに戻った）、確かめのスペースを閉じたときの値も、18 回で 212 MiB から 234 MiB に上がった（上がり方は回を追って小さくなった。herdr-app 0.1.15 で測った）。10 秒で戻りきらない理由と、確かめのスペースを閉じたときの値が上がり続けるか。決めるのは作業者（整形表示の図のメモリの検討の中で調べる）。
- app が使っていない絵として捨てた絵は、次に描くときに読み直す（[前提](#画像の置き場所)）。大きな画像や図のタブをいくつも裏に回してから前のタブに戻ると、戻ったタブの絵が一瞬空白になりうる（ソースからの推論。0.1.15 で空白が見えるか、どのくらいの長さかは測っていない）。成功条件 (6) は操作していないほうの絵だけを見るので、これは条件の外にある。これを受け入れるか。決めるのは作業者（整形表示の図のメモリの検討の中で測ってから）。
