# 編集・保存と外部変更

viewer での編集と保存、外でファイルが書き換えられたときの追従。[File viewer 仕様](index.md)の一部。

## 編集と保存

テキストのファイル（code、Markdown と SVG のソース表示、Mermaid 単体ファイルのソース表示）は、開いた時点から編集できる。ctrl-s で保存する。編集すると、そのタブは[固定タブ](../../../CONTEXT.md#固定タブ)になり、タブ名に未保存の印が付く。未保存の変更が無く、ファイルがディスクにあるときの ctrl-s は何もしない（ファイルが消えているときは[ファイルが消えたら](#ファイルが消えたら)に従う）。

保存はその space の machine 上のファイルに書く。書き込みは一時ファイルに書いてから置き換える形で行い、途中で失敗してもファイルが半端な内容にならない。保存に失敗したら理由を知らせ、編集内容はタブに残す。

- 成功条件: WSL の space で `a.js` を書き換えて ctrl-s を押すと、WSL 上の `a.js` が書き換えた内容になり、タブ名の未保存の印が消える。約 370 KB のファイルでも保存できる。
- 反例: 保存の途中で失敗して、ファイルが途中までの内容になる。保存に失敗したのに未保存の印が消える。
- 確かめ方: 書き込む内容の分割と組み立ての処理は単体テストで確かめる（分割した断片を連結すると元の内容に戻ること）。実機で保存し、WSL 側で中身を比べる。

## 保存前のディスク確認

保存の直前に、そのタブの基準（内容を読み込んだとき、または最後に保存したときのディスクの内容。下書きを復元したタブでは、下書きに記録したディスクの状態）と、今のディスクの内容が同じかを確かめる。違っていたら保存を止めて、次の 3 つから選ばせる。

- ディスクの内容で読み直す（自分の編集は捨てる）
- 自分の内容で上書きする
- やめる（何もしない。編集は残る）

- 成功条件: タブで編集中に、エージェントが同じファイルに 1 行追記した。ctrl-s を押すと保存は行われず、3 つの選択肢が出る。「やめる」を選ぶと、ディスクにはエージェントの追記が残っている。
- 反例: 確認なしに上書きして、エージェントの追記が消える。
- 確かめ方: 実機でタブの編集中にターミナルからファイルに追記し、ctrl-s を押して表示とディスクの中身を見る。

## 下書き

未保存の変更があるタブは、その内容を[下書き](../../../CONTEXT.md#下書き)として残す。下書きは、編集している間 3 秒おきに更新し、タブが閉じられるときにも書く。こうして、タブを閉じたとき・アプリを終了したとき・アプリが異常終了したときのどれでも、数秒前までの編集が残る。閉じる前に止める仕組みはアプリに無いため、閉じるときの確認ダイアログは出さない。保存すると、そのタブの下書きは消える。

下書きは app home 直下の `file-viewer-drafts/` に 1 つずつファイルとして置き、machine とパスで、どのファイルの下書きかを見分ける。同じファイルに下書きが複数あってもよい（別の space で同じファイルを編集したときなど）。下書きには、下書きを取った時点のディスクの状態と、取った時刻も記録する。

ファイルを開いたとき、そのファイルの下書きのうち、開いている viewer のタブのどれのものでもない下書きがあれば、「復元 / 破棄」を選ばせる。複数あれば新しい順に並べ、どれを復元するかを選ばせる。

- 復元すると、下書きの内容が未保存の編集としてタブに入る。復元は編集として扱い、プレビュータブで復元したらそのタブは固定タブになる。保存前のディスク確認の基準は、下書きに記録したディスクの状態になる。下書きを取った後にディスクが変わっていたら、「下書きの後にディスクが変わっている」と知らせる。保存しようとすると[保存前のディスク確認](#保存前のディスク確認)が働く。
- 復元か破棄を選んだ下書きは消える。複数あったとき、選ばなかった下書きは、破棄するまで残る。
- 最後に更新してから 30 日たった下書きは自動で消える。

- 成功条件: `a.js` を編集してタブの × で閉じ、もう一度 `a.js` を開くと「復元 / 破棄」が出て、復元すると閉じる前の編集が戻る。編集中にアプリのプロセスを強制終了して起動し直しても、3 秒前までの編集が復元できる。
- 反例: 閉じた瞬間に編集が消える。異常終了で編集が消える。復元後、ディスクの変化に気付かずに上書きしてしまう。2 つの space の下書きのうち片方が黙って消える。
- 確かめ方: 下書きの見分け方（machine とパスから下書きを特定し、新しい順に並べる処理）と期限の判定は単体テストで確かめる。実機で閉じて開き直す、強制終了して起動し直す。

## 外で書き換えられたら追従する

表示中の viewer のタブは、2 秒ごとにディスク上のファイルが[保存前のディスク確認](#保存前のディスク確認)と同じ基準から変わったかを確かめる。自分の保存は外部変更と見なさない。表示していないタブは確かめない（表示されたときに確かめる）。WSL などアプリと別の machine ではファイル監視が使えないため（[mod 開発ガイド](../../guides/herdr-app-mod-development.md#この環境の構成)）、定期確認にしている。アプリと同じ machine では、ファイル監視で変化に気付いたときにも確かめてよい。

- 未編集のタブは、変わっていたら自動で読み直して表示し直す。画像はコピーし直し、Markdown の整形表示と Mermaid 図は描き直す。
- 編集中のタブは、変わっていたら「ディスクの内容が変わった」と知らせ、「ディスクの内容で読み直す / 自分の編集を続ける」を選ばせる。続けた場合、同じ変化はもう知らせない。ディスクがさらに変わったら、また知らせる。保存のときは[保存前のディスク確認](#保存前のディスク確認)が働く。

- 成功条件: viewer で `a.md` を表示している間に、エージェントが `a.md` を書き換えると、2 秒ほどで整形表示が新しい内容になる。
- 反例: 開き直すまで古い内容のまま。編集中の内容が、知らせなく読み直しで消える。
- 確かめ方: 実機で表示中にターミナルからファイルを書き換え、`herdr-app shot` で見る。

## ファイルが消えたら

開いているファイルがディスクから消えたら（削除・名前の変更）、タブは残して「ファイルが無くなった」と表示する。表示していた中身と未保存の編集は残す。保存しようとすると（未編集でも ctrl-s で）、ファイルを作り直すかだけを確認する（ディスク確認の 3 択は出さない）。ファイルが戻ってきたら、[外で書き換えられたとき](#外で書き換えられたら追従する)と同じに扱う。

- 成功条件: 表示中の `a.js` をターミナルで削除すると、タブに「ファイルが無くなった」と出て、中身は表示されたまま。ctrl-s を押すと作り直すか聞かれ、作り直すと `a.js` が元に戻る。
- 反例: タブが勝手に閉じる。中身が消える。
- 確かめ方: 実機でファイルを削除し、`herdr-app shot` で見る。

## 文字コードと改行

UTF-8 として読む。改行（LF / CRLF）と、末尾の改行の有無は、読んだときのまま保って保存する。UTF-8 として読めない部分（置換文字 U+FFFD になる部分）があれば UTF-8 でない可能性があると判定し、開いたときにそのことを知らせ、そのタブは読み取り専用にする（中身は文字化けしたまま表示する）。

- 成功条件: CRLF のファイルの 1 行を書き換えて保存すると、`git diff` に出るのはその 1 行だけ。
- 反例: 保存すると全行の改行が LF になり、全行が差分に出る。
- 確かめ方: 改行と末尾改行の保持の処理を単体テストで確かめる（読んだ内容を編集して書き戻す内容を作り、改行の種類を比べる）。実機で保存して `git diff` を見る。

## 見送った案

- 読み取り専用にする — 「ほぼ参照、たまにちょっと編集」の編集の手段が無くなる。保存の試験が通った
- 既定は読み取り専用で「編集」ボタンで切り替える — 編集のたびに 1 手増える
- 保存時に必ずディスクの内容で読み直す / 確認せず上書きする — 自分かエージェントの変更が失われる
- 閉じたら未保存の編集を破棄する — うっかり閉じると編集が消える
- 閉じる前に確認ダイアログを出す — 閉じる前に止める仕組みがアプリに無い（タブバーまで複製すれば可能だが範囲が広がる）
- ディスクが変わっていたら下書きを捨てる — 自分の編集が黙って消える
- 下書きを閉じたときと終了時だけ書く — 異常終了や裏のタブで編集が消えうる
- 同じファイルの下書きは後から取ったもので置き換える — 先に閉じた方の編集が黙って消える
- 外部変更の知らせを保存か読み直しまで出しっぱなしにする — ずっと表示が残る
- UTF-8 でないファイルを開けないファイルとして扱う — 一部だけ化けているファイルも全く見られない
- 外部変更を知らせるだけ / 何もしない — エージェントの作業を追うたびに手間か、古い内容を最新と勘違いする
- 確認の間隔を 5 秒にする — 反映が遅い
- 改行を LF に揃えて保存する — CRLF のファイルで全行に差分が出る
