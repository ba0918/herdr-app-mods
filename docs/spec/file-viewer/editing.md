# 編集・保存と外部変更

viewer での編集と保存、外でファイルが書き換えられたときの追従。[File viewer 仕様](index.md)の一部。

## 編集と保存

テキストのファイル（code、Markdown と SVG のソース表示、Mermaid 単体ファイルのソース表示）は、開いた時点から編集できる（[UTF-8 でないファイル](#utf-8-でないファイル)は読み取り専用）。ctrl-s で保存する。編集すると、そのタブは[固定タブ](../../../CONTEXT.md#固定タブ)になり、タブ名に未保存の印が付く。未保存の変更が無く、ファイルがディスクにあるときの ctrl-s は何もしない（ファイルが消えているときは[ファイルが消えたら](#ファイルが消えたら)に従う）。

保存はその space の machine 上のファイルに書く。書き込みは一時ファイルに書いてから置き換える形で行い、途中で失敗してもファイルが半端な内容にならない。保存に失敗したら理由を知らせ、編集内容はタブに残す。

- 成功条件: WSL の space で `a.js` を書き換えて ctrl-s を押すと、WSL 上の `a.js` が書き換えた内容になり、タブ名の未保存の印が消える。約 370 KB のファイルでも保存できる。
- 反例: 保存の途中で失敗して、ファイルが途中までの内容になる。保存に失敗したのに未保存の印が消える。
- 確かめ方: 書き込む内容の分割と組み立ての処理は単体テストで確かめる（分割した断片を連結すると元の内容に戻ること）。実機で保存し、WSL 側で中身を比べる。

## 保存前のディスク確認

保存の直前に、そのタブの基準（内容を読み込んだとき、または最後に保存したときのディスクの内容。下書きを復元したタブでは、下書きに記録したディスクの状態）と、今のディスクの内容が同じかを確かめる。違っていたら保存を止めて、次の 3 つから選ばせる。

- ディスクの内容で読み直す（自分の編集は捨てる）
- 自分の内容で上書きする
- やめる（何もしない。編集は残る）

- 成功条件: タブで編集中に、エージェントが同じファイルに 1 行追記した。ctrl-s を押すと保存は行われず、3 つの選択肢が出る。「やめる」を選ぶと、ディスクにはエージェントの追記が残っている。
- 反例: 確認なしに上書きして、エージェントの追記が消える。
- 確かめ方: 実機でタブの編集中にターミナルからファイルに追記し、ctrl-s を押して表示とディスクの中身を見る。

## 下書き

未保存の変更があるタブは、その内容を[下書き](../../../CONTEXT.md#下書き)として残す。下書きは、編集している間 3 秒おきに更新し、タブが閉じられるときにも書く。こうして、タブを閉じたとき・アプリを終了したとき・アプリが異常終了したときのどれでも、数秒前までの編集が残る。閉じる前に止める仕組みはアプリに無いため、閉じるときの確認ダイアログは出さない。保存すると、そのタブの下書きは消える。

下書きは app home 直下の `file-viewer-drafts/` に置き、machine とパスで、どのファイルの下書きかを見分ける。同じファイルに下書きが複数あってもよい（別の space で同じファイルを編集したときなど）。下書きには、下書きを取った時点のディスクの状態と、取った時刻も記録する。下書きを書いている途中でアプリが止まっても、その前に書き終えた下書きは残り、復元の候補になる。

ファイルを開いたとき、そのファイルの下書きのうち、開いている viewer のタブのどれのものでもない下書きがあれば、「復元 / 破棄」を選ばせる。複数あれば新しい順に並べ、どれを復元するかを選ばせる。

- 復元すると、下書きの内容が未保存の編集としてタブに入る。「復元 / 破棄」に答える前に打ち込んでいても、確認は挟まず下書きの内容で置き換える。復元は編集として扱い、プレビュータブで復元したらそのタブは固定タブになる。保存前のディスク確認の基準は、下書きに記録したディスクの状態になる。下書きを取った後にディスクが変わっていたら、「下書きの後にディスクが変わっている」と知らせる。保存しようとすると[保存前のディスク確認](#保存前のディスク確認)が働く。
- 復元か破棄を選んだ下書きは消える。複数あったとき、選ばなかった下書きは、破棄するまで残る。
- 下書きを消している途中でアプリが止まると、その下書きが次に開いたとき復元の候補に戻ることがある。破棄すれば消える。
- 最後に更新してから 30 日たった下書きは自動で消える。

- 成功条件: `a.js` を編集してタブの × で閉じ、もう一度 `a.js` を開くと「復元 / 破棄」が出て、復元すると閉じる前の編集が戻る。編集中にアプリのプロセスを強制終了して起動し直しても、3 秒前までの編集が復元できる。下書きを書いている途中で止まっても、1 つ前に書き終えた下書きが復元できる。
- 反例: 閉じた瞬間に編集が消える。異常終了で編集が消える。下書きの書き込み中に止まり、直前の下書きごと編集が消える。復元後、ディスクの変化に気付かずに上書きしてしまう。2 つの space の下書きのうち片方が黙って消える。
- 確かめ方: 下書きの見分け方（machine とパスから下書きを特定し、新しい順に並べる処理）と期限の判定、書き込みの途中で失敗させても 1 つ前の下書きが読めることは単体テストで確かめる。実機で閉じて開き直す、強制終了して起動し直す。

## 外で書き換えられたら追従する

表示中の viewer のタブは、2 秒ごとにディスク上のファイルが[保存前のディスク確認](#保存前のディスク確認)と同じ基準から変わったかを確かめる。自分の保存は外部変更と見なさない。表示していないタブは確かめない（表示されたときに確かめる）。WSL などアプリと別の machine ではファイル監視が使えないため（[mod 開発ガイド](../../guides/herdr-app-mod-development.md#この環境の構成)）、定期確認にしている。アプリと同じ machine では、ファイル監視で変化に気付いたときにも確かめてよい。

- 未編集のタブは、変わっていたら自動で読み直して表示し直す。画像はコピーし直し、Markdown の整形表示と Mermaid 図は描き直す。
- 編集中のタブは、変わっていたら「ディスクの内容が変わった」と知らせ、「ディスクの内容で読み直す / 自分の編集を続ける」を選ばせる。続けた場合、同じ変化はもう知らせない。ディスクがさらに変わったら、また知らせる。保存のときは[保存前のディスク確認](#保存前のディスク確認)が働く。

- 成功条件: viewer で `a.md` を表示している間に、エージェントが `a.md` を書き換えると、2 秒ほどで整形表示が新しい内容になる。
- 反例: 開き直すまで古い内容のまま。編集中の内容が、知らせなく読み直しで消える。
- 確かめ方: 実機で表示中にターミナルからファイルを書き換え、`herdr-app shot` で見る。

### ほかの知らせが出ているとき

編集中のタブにほかの知らせが出ているときの、外部変更の知らせの出し方。未編集のタブは、ほかの知らせに関係なく自動で読み直す。

- 選択を待っている知らせ（[保存前のディスク確認](#保存前のディスク確認)の 3 択、[ファイルが消えたら](#ファイルが消えたら)の作り直す確認、外部変更の知らせ自体）が出ている間は、新しい外部変更の知らせを出さない。その知らせが閉じたら、次の確認で知らせる。外部変更の知らせが出ている間にディスクがまた変わっても、知らせは 1 つのまま。
- 外部変更の知らせが出ている間に保存前のディスク確認が開いたら、外部変更の知らせはその 3 択に置き換わる。
- 知らせるだけのもの（保存に失敗した理由、「下書きの後にディスクが変わっている」、viewer が出す[整形表示をしない理由](viewers.md#整形表示の上限)と[画像を押せる名前にできなかった・図を書き出せなかった・整形の準備が終わらなかった](viewers.md#整形の準備)知らせと、テーマの書き出し直しで出る[図を書き出せなかった・整形の準備が終わらなかった](mermaid.md#色)知らせ）と、[下書き](#下書き)の「復元 / 破棄」の選択が出ているときは、それを残したまま、外部変更の知らせも並べて出す。ただし「下書きの後にディスクが変わっている」で知らせた変化は、外部変更として知らせない。そこからさらにディスクが変わったら知らせる。
- 「ファイルが無くなった」の表示は、この規則に関係なく出す。選択を待つ知らせへの答え（「ディスクの内容で読み直す」など）を選んだときにファイルが無ければ、[ファイルが消えたら](#ファイルが消えたら)に従う。
- Markdown のリンクを押したときの知らせ（[リンク](viewers.md#リンク)のファイルが無い・フォルダ）はタブの中の知らせではなくアプリの通知なので、この規則の対象外。

- 成功条件: 下書きを復元して「下書きの後にディスクが変わっている」が出たまま編集を続け、そのあとエージェントがファイルを書き換えると、2 秒ほどで「ディスクの内容が変わった」も並んで出る。復元しただけで、そのあとの書き換えが無ければ「ディスクの内容が変わった」は出ない。保存前の確認の 3 択が出ている間にエージェントがファイルをもう一度書き換えても外部変更の知らせは出ず、「やめる」を選ぶと次の確認で出る。外部変更の知らせが出ている間に ctrl-s を押すと、画面に出る「ディスクの内容で読み直す」は 3 択の 1 つだけ。
- 反例: 知らせるだけのものを閉じずにいる間、外部変更に気付かない。復元した直後に、同じ変化を 2 回知らされる。3 択と外部変更の知らせで「ディスクの内容で読み直す」が 2 つ並ぶ。外部変更の知らせが 2 つ以上並ぶ。
- 確かめ方: どの知らせが出ているときに外部変更を知らせるかの判断を単体テストで確かめる（知らせの種類ごとに、出す / 出さない / 置き換える を比べる）。実機で上の場面を作り、`herdr-app shot` で見る。

## ファイルが消えたら

開いているファイルがディスクから消えたら（削除・名前の変更）、タブは残して「ファイルが無くなった」と表示する。表示していた中身と未保存の編集は残す。保存しようとすると（未編集でも ctrl-s で）、ファイルを作り直すかだけを確認する（ディスク確認の 3 択は出さない）。作り直すときにファイルが戻ってきていたら、作り直さずに[保存前のディスク確認](#保存前のディスク確認)の 3 択に移る。読み取り専用のタブは作り直さない。ファイルが戻ってきたら、[外で書き換えられたとき](#外で書き換えられたら追従する)と同じに扱う。

- 成功条件: 表示中の `a.js` をターミナルで削除すると、タブに「ファイルが無くなった」と出て、中身は表示されたまま。ctrl-s を押すと作り直すか聞かれ、作り直すと `a.js` が元に戻る。
- 反例: タブが勝手に閉じる。中身が消える。
- 確かめ方: 実機でファイルを削除し、`herdr-app shot` で見る。

## 文字コードと改行

UTF-8 として読む。

### 改行

ここでの「読んだときの内容」は、そのタブが最後にディスクから読んだ内容（開いたとき・読み直したとき）か、最後に保存した内容。

改行の種類（LF / CRLF）は行ごとに、読んだときのまま保って保存する。編集していない行は、LF と CRLF が混ざったファイルでも元の改行のまま残す。新しく入れた行・書き換えた行の改行と、編集で新しく生まれた改行（末尾に改行の無い最終行のあとに行を足したとき、末尾に改行を付けたとき）は、読んだときの内容で数の多いほうの改行にする（同数なら LF。空のファイルは LF）。どの行を「編集していない行」と見なすかの方法は[任せたこと](#任せたこと)にある。

末尾の改行の有無は、編集で触らなければ読んだときのまま。編集で付けた・消したときは、そのとおりに保存する。空のファイルに書いた内容も、末尾の改行の有無は書いたとおりに保存する。末尾に改行の無い最終行を書き換えても、改行は付けない。

- 成功条件: CRLF のファイルの 1 行を書き換えて保存すると、差分に出るのはその 1 行だけ。CRLF が 8 行・LF が 2 行のファイルで、CRLF の行である 1 行目を書き換えて保存すると、LF の 2 行は LF のままで、差分は 1 行目だけ。末尾に改行の無いファイルの最後に改行を付けて保存すると、末尾に改行が付く（CRLF が多いファイルなら CRLF）。
- 反例: 保存すると全行の改行が LF になり、全行が差分に出る。混ざったファイルで、編集していない少ないほうの改行の行が変わる。付けた・消した末尾の改行が、保存で元に戻る。
- 確かめ方: 読んだ内容と編集後の内容から書き戻す内容を作る処理を単体テストで確かめる（混ざったファイル、行の追加・削除・書き換え、末尾の改行の付け外し、末尾に改行の無い最終行の書き換え、空のファイル）。実際の窓で Enter を押したときに Editor が入れる改行が LF か CRLF かは確かめていないので、編集後の内容は両方の場合を試す。実機で保存し、git の改行変換に左右されないよう、ディスクのバイト（`od -c` など）で改行を見る。

### BOM

UTF-8 の BOM（ファイル先頭の `EF BB BF`）の有無は、読んだときの内容のまま保って保存する。BOM は Editor に見せず、編集では付け外しできない。読み込みの経路が BOM を残すか落とすかは確かめていない（`herdr-app check` では非同期の読み込みを試せない）。実装の最初に WSL の space で実機で確かめ、結果を [mod 開発ガイド](../../guides/herdr-app-mod-development.md#制約)に書く。

- 成功条件: BOM 付きの UTF-8 のファイルの 1 行を書き換えて保存すると、BOM は残り、差分はその 1 行だけ。BOM の無いファイルに BOM は付かない。Editor の先頭に見えない文字が入らない。
- 反例: 保存で BOM が消えて、先頭の行が差分に出る。編集中に気付かず BOM を消してしまう。
- 確かめ方: 書き戻す内容に BOM を付け直す処理を単体テストで確かめる（BOM あり / なし）。実機で WSL の space で BOM 付きのファイルを開いて保存し、ディスクの先頭のバイト（`od -c` など）を見る。

### UTF-8 でないファイル

UTF-8 として読めない部分があるファイルは、「UTF-8 でない可能性がある」と知らせ、そのタブを読み取り専用にする（中身は文字化けしたまま表示する）。判定は、読んだ内容に置換文字 U+FFFD があるときだけ、ファイルのバイト列が UTF-8 として正しいかを確かめて行う。正しくなければ読み取り専用にする。正しければ U+FFFD を文字として含むファイルとして扱い、普通に編集できる。バイト列を確かめられなかったとき（コマンドの失敗など）は読み取り専用にする。判定は開いたときと、[外部変更](#外で書き換えられたら追従する)で読み直すたびに行う（読み直して UTF-8 になっていれば読み取り専用を外し、UTF-8 でなくなっていれば読み取り専用にする）。読み取り専用のタブは保存も作り直しもしない。

- 成功条件: U+FFFD の文字そのものを含む正しい UTF-8 のファイルを開くと、読み取り専用にならず、編集して保存できる。Shift_JIS で書いた日本語のファイルを開くと、知らせが出て読み取り専用になる。それを表示している間にエージェントが UTF-8 で書き直すと、読み直されて読み取り専用が外れる。
- 反例: 正しい UTF-8 のファイルが、U+FFFD を含むだけで読み取り専用になる。UTF-8 でないファイルを編集・保存・作り直しできて、元のバイトが失われる。
- 確かめ方: 実機で WSL の space で両方のファイルを開き、編集できるかを見る。表示中にターミナルで文字コードを変えて読み直しを見る。バイト列が UTF-8 として正しいかの判定を mod の中で行う場合は、その処理を単体テストで確かめる（正しい列、U+FFFD を表す正しい列 `EF BF BD`、不正な列、途中で切れた列）。

## 見送った案

- 読み取り専用にする — 「ほぼ参照、たまにちょっと編集」の編集の手段が無くなる。保存の試験が通った
- 既定は読み取り専用で「編集」ボタンで切り替える — 編集のたびに 1 手増える
- 保存時に必ずディスクの内容で読み直す / 確認せず上書きする — 自分かエージェントの変更が失われる
- 閉じたら未保存の編集を破棄する — うっかり閉じると編集が消える
- 閉じる前に確認ダイアログを出す — 閉じる前に止める仕組みがアプリに無い（タブバーまで複製すれば可能だが範囲が広がる）
- ディスクが変わっていたら下書きを捨てる — 自分の編集が黙って消える
- 下書きを閉じたときと終了時だけ書く — 異常終了や裏のタブで編集が消えうる
- 同じファイルの下書きは後から取ったもので置き換える — 先に閉じた方の編集が黙って消える
- 下書きのファイルの形（数や名前）を仕様で決める — 作り替えるたびに仕様の改訂が要る
- 1 つの下書きを 1 つのファイルに上書きする — 書き込み中に止まると直前の下書きごと消える（mod の `fs/promises` には名前の変更が無く、一時ファイルから置き換えられない）
- 消した印を書いて、消す途中で止まった下書きが戻らないようにする — 印の書きかけをまた考える必要があり、得られるのはまれな確認 1 回分だけ
- 外部変更の知らせを保存か読み直しまで出しっぱなしにする — ずっと表示が残る
- UTF-8 でないファイルを開けないファイルとして扱う — 一部だけ化けているファイルも全く見られない
- 外部変更を知らせるだけ / 何もしない — エージェントの作業を追うたびに手間か、古い内容を最新と勘違いする
- 確認の間隔を 5 秒にする — 反映が遅い
- 改行を LF に揃えて保存する — CRLF のファイルで全行に差分が出る
- 混ざった改行を数の多いほうに揃えて保存する / 揃えたうえで開いたときに知らせる — 編集していない行まで差分に出る（知らせても防げず、開くたびに知らせが出る）
- 末尾の改行をいつも読んだときのままにする — 末尾の改行を viewer で付け外しできず、空のファイルから書いた内容が変わる
- 新しく生まれた改行を直前の行に合わせる — 場所によって規則が変わり、新しく入れた行と扱いがずれる
- U+FFFD を含むだけで読み取り専用にする — 正しい UTF-8 のファイルが編集できない
- 読み取り専用の知らせに「それでも編集する」を付ける — UTF-8 でないファイルで押して保存すると元のバイトが失われる
- どの知らせが出ていても外部変更を知らせない — 知らせるだけのものを閉じずにいると外部変更に気付かない
- 外部変更の知らせをいつも並べて出す — 保存前の確認と「ディスクの内容で読み直す」が 2 つ並んで迷う
- 知らせるだけのものを外部変更の知らせに置き換える — 保存に失敗した理由が、読む前に消えることがある
- 下書きの「復元 / 破棄」が出ている間は外部変更を知らせない — 下書きに答えるまで外部変更が分からない
- 復元した直後に、「下書きの後にディスクが変わっている」と同じ変化を外部変更としても知らせる — 同じ変化を 2 回知らされる
- 復元の前に打ち込んでいたら、置き換える前に確認を挟む — 復元に 1 手増え、確認の知らせが 1 種類増える
- 下書きを復元したら、その内容を改行を保つときの基準にする — 下書きの後にディスクの改行が変わっていると、編集していない行がディスクと違う改行で書かれうる
- BOM を末尾の改行と同じく編集で消せるようにする — 見えない文字なので、気付かずに消すことがある

## 任せたこと

- 改行を保つための行の対応の取り方（どの行を「編集していない行」と見なすか）。同じ内容の行や移動した行で結果が分かれうるが、編集していない行の改行が変わらない限り、どの方法でもよいため。
